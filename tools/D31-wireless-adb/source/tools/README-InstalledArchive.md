# 已安装产品APK的原件核验

本工具复用现有客户端的远程命令和文件回传，不需要为核对APK来源安装新客户端。用于追溯相同版本号但组件元数据不同的情况；不能以版本号或模板名称代替实际文件摘要。

私有配置使用既有采集工具的 `deviceId`、`deviceName`、`version`、`versionName`、`apkSha256`、`state` 和 `session` 字段，另外指定 `packageName`。当前目标仅允许取号包 `com.starnet.getnumber`，完整客户端的已安装APK及活动摘要继续复用原运行态报告。每次独立采集使用新状态目录，中断恢复则沿用原配置及状态目录。

```text
node tools/Collect-InstalledArchive.mjs <私有配置文件>
node tools/Collect-InstalledArchive.mjs <私有配置文件> --execute
```

首条只预览，第二条实际采集。工具查询包管理器的单一安装路径，核对APK大小与摘要，沿原文件通道取回，并再次核对路径、文件、构建及启动身份。拆分APK、多路径、超过8MiB、摘要变化或不完整回执均拒绝来源结论，保留已有证据；不选择其中一个文件假装完整。

`installed.apk` 为本次保全原件，`archive-receipt.json` 为身份与文件取回的结果记录。核对本地字节后才发接收回执清理服务器暂存，不能把下载成功等同包来源验证。私有状态与设备信息不上传公共仓库。

取回后使用Android工具读取清单、包名和签名，并对照已绑定正式固件的实际APK摘要。补丁资源APK、旧系统种子、当前安装APK和活动核心各有用途，不混为同一来源。比较工具不产生安装或修复动作，不自动把其它设备改成开发板的值。

设备快照使用D31原生 `/system/bin/stat`，不要求BusyBox提供该功能。每项一致性断言独立失败退出，不能依靠 `set -e` 处理连续 `&&` 中间失败。定向测试实际运行shell验证失败不会输出成功标记。

安装路径可能已被绑定挂载覆盖。当前文件摘要相同不代表包管理器缓存的组件声明相同；分析必须同时保留包管理器记录、挂载来源和正式镜像原件，不能据此自动重新安装或启用取号组件。前后核验是有限窗口的一致性证明，不是原子快照或全系统一致性证明。
