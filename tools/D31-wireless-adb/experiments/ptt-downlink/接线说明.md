## 主线可接的候选接口

`AndroidRtcDownlink(Context, File apk, String sha256, File nativeCache, MediaCapture.Clock, Events)`只保存依赖及核对APK制品对象，不调用JNI或媒体设备；`open()`才初始化APP身份的原生Peer。不得在无会话的能力检查中调用`open()`。

- `open()`：只建音频模块和Peer；使用`USAGE_MEDIA/CONTENT_TYPE_SPEECH`，不创建本地AudioSource、AudioTrack、Camera或EGL，不请求录音权限，明确`setAudioRecording(false)`，扬声器软件静音、播放默认关闭。若出现AudioRecord启动回调，按`MEDIA_PTT_CAPTURE_FORBIDDEN`停止。
- `subscribe(JSONObject)`：接收主线`rpc(subscribe)`原结果，要求首次订阅带远端offer，处理SDP并返回主线`rpc(answer)`所需body；继续复用`RtcAwait`。该方法等待SDP回调，必须放专用串行媒体线程。
- `answerAcknowledged()`：主线收到服务端`answer`成功回执后调用。不能由本地SDP或ICE成功代替。
- `enablePlayout(AudioGuard)`：只在订阅确认、ICE连接、实际远端音轨绑定、路由建立且即时守卫通过后调用。此函数会在未来真机播放，今晚禁止调用。
- `ready()`、`snapshot()`：区分订阅、ICE、实际音轨、AudioTrack启动和播放数据回调。全条件满足才ready，但音频内容仍标记`NOT_VERIFIED`；非空回调可能含静音，不能等价于扬声器可听。
- `cancel()`：可跨线程撤销资格并取消等待；不做Binder/JNI等待。主线须及时在媒体线程执行`close()`，不能只撤销资格后遗留播放。
- `close()`：先扬声器软件静音，再关闭Peer、factory、音频模块；任何释放异常明确返回`MEDIA_PTT_RELEASE_UNCONFIRMED`，主线不得释放互斥槽并启动下一媒体。

所有`Events`回调只能轻量更新主线状态或投递停止，不能在WebRTC回调线程里同步等待协商和JNI释放。状态变化才上报；播放数据回调只在首次出现时发一次changed，不逐帧触发CF请求。

## 实际远端轨道绑定

Web已报告`getReceivers()[0]`可能是本地sendonly的占位接收器。本候选绝不按索引选择接收音轨。

`DownlinkTrackBinding`从订阅结果的唯一远端audio轨读取mid，再要求来自实际`onTrack`事件的接收器身份匹配，以及完成协商后的`currentDirection`为`RECV_ONLY`或`SEND_RECV`。未知、null、SEND_ONLY、错误mid、视频轨、没有真实事件的占位轨都不能获得播放资格。PTT Peer进一步只允许一个transceiver，无本地sender track，并将方向设为RECV_ONLY。所有收到的轨默认禁用。

候选的首次订阅合同要求SFU结果含`tracks[0].location=remote`、`trackName=audio`及`mid`。目前没有D31真实订阅回执证明该响应形状，主线首次接线时需保留脱敏结构核对。若实际返回省略字段，依据原始响应和已鉴权的tracks通知明确补充绑定来源，不能直接删除校验。没有SDP或非offer的订阅结果暂不接受，不冒充已经处理全部重协商形态。

主线负责早到tracks暂存、相同通知去重、本地发布与订阅串行化、RPC结果直接解锁等待者、停止后的晚回执丢弃。PTT无需等待本地published；就绪后期限沿用Web的60秒。call会有本地sendonly与远端recvonly两个transceiver，不能复用PTT的单transceiver限制，后续应复用绑定算法和SDP操作而非整份复制PTT类。

## PTT路由及故障恢复

`AndroidDownlinkRoute.create(Context, AudioGuard idle, Runnable lost)`提供API23适配，返回`DownlinkRouteLease`。构造不申请焦点或修改设置。

1. 独立媒体线程执行`openPtt()`：无旧待恢复记录、全局空闲及MODE_NORMAL为前置条件；先持久化原扬声器状态和目标意图，提交成功才申请媒体瞬时焦点，再按需要开启扬声器。
2. 不修改模式、音量、系统麦克风静音、媒体/通话静音或强制音量最大；用户原来的零音量仍为零。
3. 任意失焦，包括短暂失焦和降低音量请求，都通知停止，不调音量后继续播。主线同时保留蜂窝/Nexui实时占用判定。
4. 结束先关闭Peer并确认播放停止，再`lease.close()`释放焦点并恢复本次扬声器改动。恢复前重新检查空闲与MODE_NORMAL；来电接管或状态不明时保留恢复记录，不覆盖新电话路由。
5. 恢复记录保存在APP私有`ptt-route-recovery`偏好中。下次初始化可调用`recover()`，仅在空闲门通过后恢复。任何恢复/记录删除失败保留错误，不能宣布cleanup_complete。新会话有待恢复记录时拒绝启动。

该恢复意图可以处理应用崩溃后留下的扬声器状态，但不是Android全局路由的原子所有权锁。用户或其它应用在会话中写入同一个值无法只靠布尔状态判别；当前采取有空闲证据才恢复的保守方式，仍需实际验证焦点接管、用户切换和系统电话抢占。不能据离线测试声称全部路由竞争已解决。

## 输出归属守卫的主线缺口

当前全局`AndroidAudioOccupancy`把任何焦点、活动输出、通信模式视为外部占用。PTT自身焦点和播放开始后直接复用该总判定会误杀；但删去对应检查会放过其它应用。

因此接线前仍需主线提供本会话实际AudioTrack输出身份和新鲜Flinger/Policy证据，并结合焦点、模式、路由恢复意图定向识别自身输出。蜂窝/Nexui忙或未知仍必须拒绝。`enablePlayout`传入的守卫不能是空函数，也不能把所有输出豁免。本目录测试的空守卫只用于隔离路由算法，不能复制进生产接线。

第一轮不播放的协议验收可停在订阅应答、ICE和实际轨绑定，不能据此将PTT标记可用。今晚保持不播放、不设备操作；真正播放与输出归属采集由主线在允许时安排。

## call独立合同及下批事项

call是网页与D31双向通话，不是蜂窝/SIP拨号。本轮不启动call，也不更改140的MIC/16 kHz合同。

- 播放使用`USAGE_VOICE_COMMUNICATION/CONTENT_TYPE_SPEECH`，通信模式候选为`MODE_IN_COMMUNICATION`，焦点与通话流一致。是否用机身话柄或免提出声需明确选择和实证，不能一律强制外放。
- 采集`MediaRecorder.AudioSource.VOICE_COMMUNICATION`需单独验证D31厂商处理、采样率、AEC/NS、实际Flinger/Policy输入形状。当前MIC归属规则不能直接通过source=7的通信输入，不能删除source检查，须依据实际PID/session与通信输入双源原件新增专门合同。
- D22使用MIC、禁硬件AEC/NS，并按call显式开启软件回声消除/降噪/高通。它的源码注释指出D22厂商通信音源曾有削顶，不能由此推断D31也如此；若D31的VOICE_COMMUNICATION也有同类问题，应以受控双向试验决定替代，不在本批顺带改变音效。
- 模式和扬声器原值先持久保存，改动字段分别记意图；音量默认不写。如未来允许用户显式调整，必须按设备路由分别恢复，不把听筒音量当成扬声器原值，绝不默认最大音量。
- call应在本地发布与远端订阅分别完成、实际采集与播放都存在、ICE及guard通过后ready。一个方向成功不能代表双向成功；不以PCM或RTP能量为零自动拒绝。
- 短暂/永久失焦、Nexui或蜂窝来电、换音频设备、断网、网页结束、APP退出、核心失联均要停止并保存恢复结果。服务重启后的恢复不能覆盖后来电话已接管的状态。

### 主线执行适配映射

`PttSessionController`接受`Operations`适配器，不重新定义共享Offer或传输。主线已有同源WSS和已验证邀请继续作为来源；构造传当前邀请的过期时间。适配器各操作必须落实如下顺序：

| 动作 | 对应操作 |
| --- | --- |
| `open` | 启动观察器并取得新鲜空闲样本；守卫通过后保存/建立路由，再打开PTT Peer。不得以空缓存或空守卫代替。 |
| `send` | 走已有WSS；回执调用控制器`receive`。 |
| `subscribe` | 调用Peer的同名方法，返回answer正文。 |
| `answerAcknowledged` | 标记服务端应答已确认。 |
| `prepareMuted` | 使用本会话焦点归一后的空闲守卫调用Peer静音播放入口。 |
| `outputProof` | 实际AudioTrack尚未创建或新样本尚未取得时返回0；先读取私有实际session交给观察器，再调用`requireOwnedOutput`。只有未来真实归属合同通过才能返回1；已取得的活动格式未验证须抛具体错误，不继续等到超时。 |
| `playbackFrames` | 返回本会话实际播放回调标记；不能来自占位receiver或网络能量统计。 |
| `unmute` | 重新执行`requireOwnedOutput`后调用Peer解除静音。 |
| `cancel` | 仅撤销Peer资格/取消等待，不能在核心循环执行JNI释放或Binder等待。 |
| `close` | Peer停止并释放后，观察器取得新鲜停止后空闲证据，再恢复路由，最后关闭观察器。若观察器先关闭会清掉恢复所需缓存，顺序不可颠倒。任何未知清理结果保留互斥槽和恢复日志。 |

`Operations`里的测试替身返回1只是测试状态机的成功分支，不能复制进生产。生产`PttOutputGuard.requireOwnedOutput()`目前始终明确拒绝：无输出时报`MEDIA_OUTPUT_NOT_STARTED`，活动格式未验证时报上述具体缺口。这是证据尚缺的真实状态，不是偷偷开放的能力。

### 必须从D31补取的字段

当前还不能承诺明天只剩听声音验收；先需要一轮被明确允许的**软件静音AudioTrack取证**。它仍会操作音频设备，本任务本轮没有执行。该轮不能解除静音，也不能用延长时间或降低检查替代原件。

- 实际WebRTC AudioTrack对象的`getAudioSessionId/getSampleRate/getChannelCount/getAudioFormat/getStreamType`和本次APP PID，核对回调身份与私有样本关联。
- 同轮完整Flinger中`Name Active Client Type Fmt Chn mask Session fCount S F SRate L dB R dB Server Main buf Aux Buf Flags UndFrmCnt`的活动行全部列，活动总数、Global session refs、输出线程handle/设备/格式/采样率、效果链/FastMixer状态。
- 同轮完整Policy中对应输出handle、`Devices`、采样率/格式/声道、对应stream的`refCount/muteCount`及Audio Patch的Mix到扬声器关系，确认是否有其它输出同时活动。
- 同窗口蜂窝/Nexui状态、音频模式、焦点获得/失去事件、流活动布尔值，以及软件静音启停前后的原始路由值。
- 停止后的上述两源原件及原路由恢复回读。音频PCM不保存。
