# Windows工具1.6.10流程及分区查询修正

记录日期：2026年9月26日。

## 已确认的问题

1. 界面把手动“只读检查通过”作为清空确认框及“开始刷机”的解锁条件，改变了原先一键执行检查与刷机的流程。备份选择无法解除该条件，因此勾选或取消备份均不能开始。
2. Windows PowerShell 5.1调用原生ADB时会剥离查询命令中的双引号，`printf "|"`因此变成非法管道。只修正输出分隔符仍不够：`tr -d "\n"`失去引号后不能去掉换行，正常的分区记录被拆成两行，格式匹配失败。
3. 旧的进程启动异常处理没有区分启动失败和启动后日志读取初始化失败，后者可能在后端尚未退出时提前解除界面锁定。

用户提供的日志停止在分区映射检查，未进入刷写。该日志本身不能证明分区损坏，也不能证明第三方系统不兼容。

## 修正后的流程

有线D31识别成功、选定固件通过长度和SHA-256验证后，即可勾选清空数据确认。点击“开始刷机”并确认目标后，工具重新自动检查设备；检查通过后，根据备份选择执行备份或直接进入刷机后端。备份失败不会刷机。

“只读检查”保留为独立、可选入口，不需要固件，不会自动继续备份或刷机。旧检查成功结果不能代替本次自动检查。忙碌期间禁止更换目标、固件或重复开始，退出回调必须属于当前后端进程。

分区查询在Windows旧式原生传参模式下保留双引号，新版PowerShell按其实际参数模式处理。分区读取失败时显示保留换行的原始返回内容；块设备、容量、起始位置和重叠检查没有取消。

## 第三方系统的判断边界

当前Android构建指纹不同不是拒绝理由。同一D31平台安装其他系统后，只要实际分区及安装入口符合当前固件要求，就可以使用本工具。

配套固件仍为1.4.5，基础APK仍为193。本次没有修改或重签固件。1.4.5安装器自身在写入system前会逐字核对现有boot与Recovery，并保留这两个分区。如果另一个系统也修改了它们，摘要差异表示超出当前安装器已支持的范围，不等于机器损坏；只删除Windows检查会把失败推迟到Recovery，不能解决兼容问题。本次未取得朋友设备的boot/Recovery原件，不声称已完成该设备整机实刷验收。

## 验证方式

- 界面使用实际窗体和异步进程回调，后台替身仅运行本地脚本；检查有备份、无备份、失败、缺失通过标记、目录创建失败、维护拒绝、独立检查和目标状态变化。
- 分区测试抽取生产函数，经Windows PowerShell、原生EXE参数接收、隔离BusyBox shell执行实际查询命令；只替换设备节点及sysfs数据，不返回预制格式字符串。旧命令的管道错误和换行错误均可复现。
- Windows PowerShell 5.1分区回归42项通过，新版PowerShell的Windows与Legacy参数模式合计82项通过。有效布局可读，普通文件、缺失字段、错误磁盘、容量错误、重复及重叠仍被拒绝。
- 最终EXE须完成构建器回归、资源一致性及公开下载摘要检查；发布摘要见Windows源码目录对应版本清单。本次未对真实设备执行刷写、擦除或重启。
