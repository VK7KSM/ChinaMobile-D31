# D31 1.4.6 完整刷机说明

## 修改原因

旧版1.4.5虽然包含配套的`boot.img`和`recovery.img`，但只核对它们、不写入。第三方系统修改过这两个分区后，1.6.10会因摘要不同停止。这不能证明硬件不兼容，也不能满足将同硬件设备完整刷成项目系统的要求。

1.4.6与Windows工具1.6.11配套使用，改为完整刷机，不再要求旧`boot`和`Recovery`内容与开发机相同。仍核对D31产品平台、实际块设备映射、容量和分区是否重叠，避免写错位置。

## 写入范围

| 内容 | 处理 |
| --- | --- |
| `system` | 用包内系统镜像覆盖 |
| `logo` | 用包内开机图片覆盖 |
| `userdata` | 清空原文件、应用数据及账号，安装随包应用和默认配置 |
| `cache` | 清理旧系统缓存，保留`/cache/recovery`诊断目录，不格式化运行中的缓存分区 |
| `boot` | 安装包内配套启动镜像并逐字回读 |
| `recovery` | 安装包内配套恢复环境并逐字回读 |
| 设备身份、校准、`nvram`、`nvdata`、`protect1/2`等 | 保留本机原件，不克隆开发机身份 |
| `preloader`、`lk`、分区表 | 不写入 |
| 外接U盘、TF卡 | 不清空 |

原镜像备份是失败时的救急原件，不会自动恢复进新系统。这里的清空是删除旧数据并重建运行状态，不是保证旧数据无法取证恢复的安全擦除。

## 安装顺序

1. 在Windows点击“开始刷机”，确认后自动执行检查；无需先手动点击“只读检查”。
2. 按用户选择备份完整原系统，上传并核验完整签名ZIP。
3. 自动将当前`boot`和`Recovery`原像保存到电脑，并核对设备端、电脑端摘要。取消完整系统备份也不会取消这两个小备份。
4. 若旧`Recovery`不是包内目标镜像，先在当前可运行系统中写入配套`Recovery`并回读。这样不会依赖第三方`Recovery`是否接受本项目签名。
5. 进入配套`Recovery`，预检包内启动镜像，再安装系统、开机图片、应用和默认配置，最后完成`boot`和`Recovery`写入与回读。
6. 首次启动后核对构建、启动镜像、预装文件、桌面补丁和系统服务；只有全部通过才报告刷机完成。

单独“只读检查”不备份、不上传、不写分区、不重启。写入失败或结果不确定时保留电脑原像和操作日志，不自动重试分区写入。写入开始后不要断电或让电脑休眠。

## 载荷和验收边界

本次保持已发布1.4.5的系统、应用、配置、音量加激活入口和设备端优化载荷不变；只改安装器、包内清单及配套Windows流程。完整elfRemote仍为194，基础首次引导APK仍为193，不借本次更换业务组件。

新包已完成重新签名、整包签名验证及新旧载荷逐项摘要比较。原生146安装器45项、144/145旧分支各4项、Windows完整后端70项、窗体流程92项通过；另有针对迁移、备份、命令引号及维护入口的独立故障测试。离线通过不代表第三方系统设备已实刷通过；实际清空安装及首次启动仍需在目标D31验收。
