# D31刷机工具使用说明

## 工具定位

`D31-Flash-Tool-v1.3.1.exe`用于给每一台目标D31执行以下闭环：

1. 校验官方签名刷机包。
2. 通过有线`eth0`上的TCP ADB识别目标机。
3. 只读核对构建、分区布局、原厂Recovery、root和存储空间。
4. 从这台目标机读取原始`system`、`boot`以及关键身份和校准分区，创建只适用于该机的急救恢复包。
5. 要求用户把急救目录复制到FAT32 TF卡或U盘，并在刷机前实际运行只读`D31_RESCUE_TEST.zip`。
6. 只有TEST显示PASS并完成数据清除确认后，才允许执行正式Recovery刷写。

工具不使用基于母机的通用急救镜像。不同生产批次可能采用不同元件、分区布局、Recovery或签名证书；急救包必须从即将刷写的那一台D31现场生成。

## 强制标准流程

1. 解压`D31_SVP3390_Windows_Flash_Tool_v1.3.1.zip`，保持所有文件和子目录的位置不变。
2. 双击`D31-Flash-Tool-v1.3.1.exe`。
3. 点击“选择刷机包”选择官方ZIP，或点击“从GitHub下载”。工具会核对文件长度和完整SHA-256。
4. 给D31接入稳定电源和有线网络，在界面填写目标机`eth0`的IPv4地址。
5. 点击“检测D31”，再点击“只读检查”。这两个阶段不写分区、不改设置、不重启。
6. 点击“创建本机急救包”。读取和压缩1.5GB原始`system`需要较长时间，期间不得断电、拔网线、休眠电脑或关闭工具。
7. 创建完成后，打开工具显示的本机急救目录。把名为`复制到TF卡或U盘的整个目录`的目录及其全部文件原样复制到FAT32介质。不要复制名为`禁止公开的本机私有备份`的目录到公共介质或网络。
8. 在D31仍能正常启动时，亲自验证该机进入原厂Recovery的实体键方法。插入介质，在Recovery中选择`D31_RESCUE_TEST.zip`。
9. 只有屏幕明确显示`D31 rescue media test completed: PASS`才算通过。TEST只读取并校验签名、介质文件、分区尺寸、Recovery、`proinfo`、`system`和`boot`，不会写分区，也不会清除数据。
10. 重启回Android，在图形工具中勾选“已运行TEST看到PASS”和“确认清空数据”。此时“开始刷机”才会开放。
11. 点击“开始刷机”并确认。PowerShell后端会再次独立核对急救包是否属于当前连接的D31；任何不一致都会在写Recovery命令前拒绝。
12. 第8/9阶段开始后，D31会重启进入Recovery。此时不得断电、关闭工具或让电脑休眠。首次启动可能因重建`userdata`和ART缓存而明显变慢。

## 本机急救包内容

### 可复制到FAT32介质的目录

- `D31_RESCUE_SYSTEM.img.gz`：该机刷机前的完整原始`system`分区。
- `D31_RESCUE_BOOT.img`：该机刷机前的完整原始`boot`分区。
- `D31_RESCUE_MANIFEST.txt`：分区尺寸、载荷哈希以及Recovery和设备绑定信息。
- `D31_RESCUE_TEST.zip`：只读介质与本机绑定测试入口。
- `D31_RESCUE_UPDATE.zip`：真正执行恢复的入口。
- `急救恢复说明.txt`和`SHA256SUMS.txt`。

### 只能私下保存的本机备份

工具另存`nvram`、`nvdata`、`protect1`、`protect2`、`proinfo`、`recovery`、`secro`、`seccfg`和`frp`。这些文件可能包含设备身份、校准和安全状态，只能保存给原机工程恢复，禁止上传GitHub、R2、网盘或复制给另一台D31。

急救包不保存`userdata`，因此不包含SIP、邮箱、Telegram、Zello、Wi-Fi账号、密码、通信录、邮件或其他个人数据。

## 刷砖后的卡刷恢复

这里的“刷砖”是指本工具写入`system`或`boot`后Android无法启动，但原厂Recovery仍可进入。本工具永远不写`recovery`分区。

1. 保持稳定供电，插入首次刷机前已经通过TEST的FAT32 TF卡或U盘。
2. 使用该机已经亲自验证过的实体键组合进入原厂Recovery。
3. 选择对应的外部介质入口，再选择`D31_RESCUE_UPDATE.zip`。
4. 安装器会先完成所有绑定、长度和SHA-256校验，全部通过后才写回该机原始`system`和`boot`。
5. 出现`D31 emergency restore completed`后重启。
6. 若出现`ERROR 22`，表示`system`和`boot`已经恢复并回读校验通过，但自动清除`userdata`失败；在Recovery中手动执行`Wipe data/factory reset`后重启。

卡刷目录只适用于创建它的原机。另一台D31即使外观和型号相同，也不得共用。

## 不同批次的处理原则

- 工具会读取目标机自己的原始分区，不假定所有D31内部完全相同。
- 当前官方优化固件仍有明确适用范围。若构建指纹、`system`、`boot`、`userdata`尺寸或Recovery信任基线不同，工具必须拒绝刷入当前固件。
- 被拒绝不代表机器有故障，而是说明该批次需要先做只读分析并为它制作单独兼容的刷机包和签名入口。
- 不得通过修改脚本、跳过哈希或伪造勾选状态强行刷写。

## 全新原厂D31打开ADB

1. 在原厂拨号键盘输入`*#233#*`并按绿色拨出键，进入Android系统设置。
2. 若没有“开发者选项”，进入“关于设备”，连续点击“版本号”7次；返回后打开“USB调试”。该开关是Android调试总开关，实际连接走有线TCP，不需要USB数据线。
3. 在“安全”中打开“未知来源”，并打开蓝牙。
4. 在拨号键盘输入`*#223#*`并按绿色拨出键，进入Android原生桌面。
5. Windows运行`fsquirt`，把`首次引导工具\D31-wireless-adb-v1.0.apk`通过蓝牙发送给D31。
6. 在原生桌面接受文件，通过蓝牙完成通知调用Android原生包安装器。不要使用原厂阉割文件管理器打开APK。
7. 安装后点击“打开”，再点击“开启无线ADB（端口5555）”。“无线ADB”是应用名称；本刷机工具只接受目标机有线`eth0`地址。

## 当前验证边界

急救入口已经完成编译、静态ARM ELF检查、ZIP结构和CRC检查、Recovery整文件签名校验及离线哈希检查。Windows工具已完成编译和离线自检。由于项目当前只有一台D31，没有执行真实分区刷写，也没有在另一批次设备上验证实体键和外部介质挂载。因此v1.3.1仍是候选工具，不能宣称已经完成量产刷机或真实卡刷恢复验收。

旧的`一键刷入D31完整系统.cmd`不再接受IP或ZIP参数，也不能绕过急救门；它只负责启动v1.3.1图形工具。
