# D31 SVP3390完整刷机包v1.1.0

## v1.4.3工具的可选电脑硬盘备份

`D31-Flash-Tool-v1.4.3.exe`默认勾选“刷机前自动备份原系统到电脑硬盘”，但用户可以取消。工具不判断这是不是第一次刷机，也不强制要求备份。v1.4.3同时提供GitHub和Cloudflare两个独立高速下载按钮，使用内置aria2 1.37.0进行多连接下载、断点续传并显示实时速度、进度和预计剩余时间。GitHub公开下载不需要账号或Token；工具禁止读取电脑上的aria2用户配置。多连接被源站限制或失败时，工具保留现有断点并自动用单连接兼容模式重试。

保留默认选项时，点击“开始刷机”后，工具先把当前D31的原始`system`、`boot`以及关键身份和校准分区保存到电脑工具目录下的`D31备份`，完成后自动继续刷机。正常刷机不需要插U盘或TF卡，也不要求运行`D31_RESCUE_TEST.zip`。

取消备份时，工具会明确提示刷机失败后没有本机急救包，但用户确认后仍可继续。后端使用独立的`-SkipBackup`路径，不会暗中备份分区。

只有D31刷坏且Android无法启动、但原厂Recovery仍可进入时，才需要把电脑硬盘急救包中的`需要抢救时复制到TF卡或U盘`目录复制到FAT32介质，并运行`D31_RESCUE_UPDATE.zip`。急救镜像只属于创建它的原机，不能用于另一台D31。

## v1.1.0完整母机基线

本版不再使用原厂`system.img`配合刷机后临场卸载。`system.img`来自当前母机的完整物理system分区只读副本，并在电脑副本中物理删除学习强国、WPS、TR-069、EMU、旧浏览器、旧日历等18个无用或风险路径。独立验证器已重新挂载签名包内解压出的镜像，确认这些路径不存在，同时确认原厂SIP电话、Nexui、IMSCC、中文输入法、计算器、屏保、EngineerMode、MTKLogger和工厂测试组件仍存在。

本版管理程序升级为`1.10.10-factory-default-security`。包内保留TLS 1.2、网络切换后的SIP重新注册、Firefox和Telegram主页入口、时区时钟、实体键、Zello守护、ADB 5555开机恢复、8765状态探针、IPv4与IPv6动态入站防火墙，以及8入口Nexui应用页。所有第三方应用均只包含未配置APK本体，不包含SIP、Wi-Fi、邮箱、通信录、应用登录或ADB授权数据。

该包已经完成源文件哈希、ZIP结构、ZIP CRC、Recovery整文件密码学签名、安装器、APK版本与签名、系统功能文件、`boot.img`以及`system.img.gz`完整解压和只读挂载回验。母机上的功能修改已经分别验收，但v1.1.0安装器尚未在备用D31执行真实分区刷写。当前状态是“完整刷机候选已完成离线验证，等待首台同型号备用机实刷验收”，不能写成已经完成真实刷机验证。

`v1.0.0`和`v1.0.1`的安装器TLS对齐不足，禁止使用。

## 全新封锁机的入口

D31的两个USB-A口目前只证明是USB主机口，可用于U盘、键盘和鼠标。尚未发现可以让D31作为USB设备连接电脑的接口，禁止使用USB-A对USB-A线强行连接。本刷机流程不依赖USB物理连接，但仍建议在Android开发者选项中打开“USB调试”总开关，再由TCP 5555承载ADB。

全新原厂D31已经验证的完整入口是“原厂拨号暗码 -> Android原生桌面或设置 -> 蓝牙`OBEX OPP` -> 原生包安装器 -> TCP ADB”。按以下顺序操作：

1. 给D31接入有线网络，从路由器后台确认其IPv4地址并记下。此处的“无线ADB”指TCP ADB，可以完全通过有线网卡使用，并不要求D31连接Wi-Fi。
2. 回到D31原厂电话界面的拨号键盘，依次输入：

   ```text
   *#223#*
   ```

   然后按D31的绿色拨出键。这不会发起普通电话，而是进入Android原生`Launcher3`桌面和完整应用列表。
3. 如果只需要直接进入Android系统设置，可在原厂拨号键盘输入：

   ```text
   *#233#*
   ```

   再按绿色拨出键。该暗码会直接打开Android系统设置，不需要先进入原生桌面再寻找“设置”图标。
4. 在“设置”中完成以下准备：

   - 如果尚未显示“开发者选项”，进入“关于设备”，连续点击“版本号”7次，再返回上一级。
   - 进入“开发者选项”，打开“USB调试”。这里打开的是Android调试总开关，后续数据实际走有线以太网TCP 5555，不需要USB数据线。
   - 不需要为此刷机打开“OEM解锁”；本流程不走Fastboot，也不解锁Bootloader。
   - 进入“安全”，打开“未知来源”，否则Android 6会阻止从蓝牙接收的APK进入安装器。
   - 进入“蓝牙”，打开蓝牙并使D31处于对电脑可见的状态。
5. 让Windows电脑与D31蓝牙配对：在Windows蓝牙设置中选择D31，确认电脑和D31显示的配对码一致，并在D31上确认配对。配对完成后，D31端应显示电脑为已配对，而不是一直显示“正在配对”。
6. 让D31停留在Android原生桌面，不要返回原厂Nexui桌面。在Windows上按`Win+R`，输入`fsquirt`并回车，选择“发送文件”、目标D31，然后选择：

   `首次引导工具/D31-wireless-adb-v1.0.apk`

7. D31出现蓝牙文件接收提示时，立即点击“接受”。使用原生桌面的目的，正是避免原厂Nexui把接收提示覆盖或在约1秒后自动消失。
8. 传输完成后，点击D31通知栏中的“蓝牙接收完成”通知或直接点击收到的APK，选择用Android“包安装程序”打开。如果没有自动弹出，从原生桌面打开通知栏的传输完成记录；不要使用被阉割的原厂“资源管理器”，它不能正常调用APK安装器。
9. 在原生包安装器中点击“安装”。安装完成后立即点击“打开”；该最小版本在原厂桌面上可能没有清晰的图标或名称，不要关闭安装完成页后再去寻找。
10. `D31 无线 ADB 启动器`打开时会自动尝试开启TCP ADB。等待页面初次处理完成后，再手动点击一次“开启无线 ADB（端口 5555）”。页面应显示“无线 ADB 已启动：设备地址:5555”和“127.0.0.1:5555 正在监听”。
11. 这个`v1.0`是唯一在原始未改D31上完成过蓝牙安装、5555启动和root ADB连接验证的最小引导版。首次引导不使用后续复杂版本替代它。

电脑端使用以下PowerShell命令，把`<D31-IP>`替换为实际有线地址：

```powershell
$adb = 'C:\Dev\android-sdk\platform-tools\adb.exe'
$serial = '<D31-IP>:5555'
& $adb -P 5041 connect $serial
& $adb -P 5041 -s $serial shell id
& $adb -P 5041 -s $serial shell getprop ro.build.fingerprint
```

`id`必须返回`uid=0(root)`，构建指纹必须与本文“精确适用范围”完全一致。原厂固件是`userdebug/test-keys`，且`ro.adb.secure=0`，因此已验证的这一批D31不需要OEM解锁、Bootloader解锁或USB数据线才能得到root ADB。

因为`*#233#*`已能直接打开系统设置，通常不再需要设置探针。只有暗码入口在另一固件修订上失效，或最小ADB程序不能打开5555且需要额外状态页时，才通过蓝牙安装备用的：

`首次引导工具/D31-setup-probe.apk`

它可以打开原生设置和开发者选项以核对调试状态。如果同一外观的新机构建指纹不同、端口5555仍不监听，应停止刷机；这可能是另一硬件或固件修订版，不应绕过安装器的机型检查。

## 数据与身份边界

刷机时会清空整个`userdata`，所以原设备上的应用数据和账号不会保留。包内只有APK本体和无账号功能文件，不含：

- SIP账号、密码或通信录；
- 邮箱账号、邮件、令牌或密码；
- Telegram和Zello登录状态；
- Wi-Fi名称或密码；
- ADB授权密钥、Android应用数据、数据库或偏好设置。

刷机包不会写入`recovery`、`nvram`、`nvdata`、`protect1`、`protect2`、`proinfo`、`keystore`、`oemkeystore`或`frp`，因此不会复制母机的硬件校准、设备身份和密钥材料。

原厂Nexui中若干界面示例图片含厂家预置的演示号码。这些图片与未修改的原厂APK逐文件哈希一致，不是当前D31运行时写入的通信录、通话记录或账号配置。

## 首台备用机的刷机流程

### 第一步：准入检查与可选备份

1. 只在另一台构建指纹完全相同的D31上测试，不在当前母机上试刷。
2. 确认root ADB后，先保存`getprop`、`by-name`分区表以及以下尺寸：

   - `system=1610612736`
   - `boot=16777216`
   - `userdata=13517717504`

3. 图形工具默认把该机的原始`system`、`boot`、`nvram`、`nvdata`、`protect1`、`protect2`、`proinfo`、`recovery`、`secro`、`seccfg`和`frp`备份到电脑硬盘；用户也可以取消备份后继续刷机。
4. 如果选择备份，私有分区可能包含设备唯一身份，只能保存并恢复到原机，不得放入GitHub、R2或通用刷机包。

### 第二步：传输并校验签名ZIP

不要解压ZIP。通过已取得的有线网络ADB传到`userdata`：

```powershell
$zip = 'C:\Dev\H13_D22\research\d31\dist\factory-flash-v1.1.0\D31_SVP3390_Factory_Flash_v1.1.0_testkey.zip'
$remote = '/data/local/tmp/D31-factory-v1.1.0.zip'
& $adb -P 5041 -s $serial push $zip $remote
& $adb -P 5041 -s $serial shell "busybox sha256sum $remote"
```

设备端输出必须精确为：

`6C4A109250EDB29257CDB64A0E3BA1E0F6C0C64E67574516C8276716F6D75841`

如果新机没有`busybox sha256sum`，应停止并换用已验证的设备端哈希工具，不得跳过传输后校验。`/cache`通常放不下1.26GB刷机包，不要把整个ZIP复制到`/cache`。

### 第三步：由正常Android自动触发Recovery

先保持D31稳定供电，再写入Recovery命令：

```powershell
& $adb -P 5041 -s $serial shell "mkdir -p /cache/recovery; printf '%s\n' '--update_package=/data/local/tmp/D31-factory-v1.1.0.zip' '--locale=zh_CN' > /cache/recovery/command; cat /cache/recovery/command; sync"
```

必须在屏幕上核对目标机型和ZIP哈希；如果选择了备份，还要确认电脑硬盘备份已经完成。首台验收时，这是最后一个可以无损停止的位置。确认后才执行：

```powershell
& $adb -P 5041 -s $serial reboot recovery
```

Recovery会读取`/cache/recovery/command`、验证ZIP整文件签名，再调用包内原生安装器。安装器会在清空`userdata`前打开ZIP并完成载荷结构预检；因此后续删除`/data/local/tmp`中的目录项时，已打开的ZIP文件描述符仍可继续读取。这一设计已完成代码和离线检查，但仍属于首台备用机真实Recovery刷写要验收的内容。

进入Recovery后网络ADB断开是正常现象。原厂Recovery虽包含USB `adbd`，但它使用USB FunctionFS；目前没有找到D31的USB设备模式物理接口，所以不把它作为首次刷机依赖。

### 第四步：首次启动与验收

1. 首次启动会重建`userdata`、扫描APK并执行ART优化，明显慢于普通重启是预期现象。期间不拔电，不因短时停留在开机画面而反复重启。
2. 进入桌面后依次验收桌面、触屏、实体键、中文输入法、有线和Wi-Fi、原厂SIP音频与视频、扬声器和麦克风、Zello守护、无线ADB及本机防火墙。
3. 所有预装应用都是未配置状态；SIP、Wi-Fi、邮箱、Telegram和Zello均需要按新设备单独配置。
4. 拉取`/cache/recovery/last_log`和当次开机日志存档。任一核心项失败时，保留现场和日志，不立即重刷。
5. 未完成上述验收前，不得把该包用于批量设备。

## TF卡或U盘急救路线

正常刷机不需要U盘或TF卡。只有用户在刷机时保留了默认备份，并且刷机后Android无法启动、但Recovery仍可进入时，才使用外部介质恢复。

在电脑的`D31备份`中找到对应设备的急救包，将`需要抢救时复制到TF卡或U盘`目录及全部文件复制到FAT32介质。进入原厂Recovery后选择`D31_RESCUE_UPDATE.zip`，它会先校验设备、分区和载荷，再恢复该机刷机前的原始`system`和`boot`。若屏幕显示`ERROR 22`，说明两个分区已经恢复并回读验证成功，但需要在Recovery中手动执行`Wipe data/factory reset`。

如果用户刷机时取消了备份，电脑中不会生成急救包，不能使用这条恢复路线。
