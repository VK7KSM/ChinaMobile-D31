# D31 1.4.1固件逐项复核

## 为什么重做这一版

1.4.0确实混入了旧文件：系统镜像的应用页仍写着“质感文件”，附带模板却是“文件管理器”；短信APK也与母机当前版本不一致。不是检查了旧下载包。另有首次启动专属问题：桌面等待超时后退出、存储服务在应用目录尚未创建时退出、权限模板没有保证通过安卓包管理器生效。

1.4.1重新以母机只读提取的物理system分区为来源，生成无账号的发行镜像。打包后再次解压最终签名ZIP，核对母机文件、权限、符号链接、应用和系统配置。朋友那台机器没有留下完整首次启动日志，因此不能把上述任何一项称为十五分钟启动和无响应的唯一根因。

## 功能与对应文件

| 项目 | 本版交付与核对方法 |
| --- | --- |
| 文件管理器、短信 | 使用当前母机APK，逐文件SHA-256核对；应用名称为“文件管理器”，短信保留双通道版本 |
| 应用页 | system模板与附带`config-tab`逐字相同，再与母机实际应用页逐项比对名称、组件及顺序 |
| Telegram、Firefox和短信主页入口 | 保留本次母机的Nexui及IMSCC补丁，先让包管理器读取原厂签名包，再按既有交接流程加载 |
| 蜂窝显示与下拉菜单 | 包含被动读取号码、运营商及网络制式的系统支持1.0.4；保留当前蜂窝菜单及顶部下拉修复 |
| 启动交接 | 慢首次启动继续低频等待，不再到180秒就放弃；初始化失败保留标记并重试，交接失败保留回滚记录 |
| U盘与TF卡 | 独立系统支持优先处理存储；命令服务等待应用目录建立，父守护监督其退出；实际卷路径动态发现，插入后确认打开 |
| 存储入口 | 保留文件管理器独立卷列表及原厂设置跳转修复，关闭原厂重复的插盘提示入口 |
| 后台任务 | 存储与维护各用独立任务队列；Firefox约180秒、Thunderbird约300秒恢复后台任务，随后关闭下一轮开机重排接收器 |
| 首启编译 | 预置八份与对应APK及安装位置匹配的Arm64缓存；Thunderbird使用`interpret-only`缓存。逐个核对DEX条目、原始头和CRC，不把优化后的DEX误说成原APK逐字副本 |
| 实体快捷键与Zello | 预置按键布局，通过首次初始化启用无障碍及通知监听；补入Zello与守护省电白名单并回读，不复制登录数据 |
| 短信、存储和蜂窝权限 | 用真实包管理器设置和回读白名单权限、默认短信及写短信操作；不再依赖仅写入权限XML |
| SIP TLS与切网 | 采用母机已验证的TLS 1.2、DNS恢复及失效连接清理库；关闭原厂TCP加速，仅修改该字段 |
| 双网口与无线 | 保留双网ARP规则和系统框架修复；仅规范目标机器自己已有的无线地址缓存，不复制母机MAC或无线账号 |
| 时钟 | 保留模拟时钟跟随系统时区的代码修复；不把母机所在时区强制写给所有用户 |
| 自动短信取号 | system内以无代码、无短信权限、四个入口关闭的占位包替换原厂取号程序；初始化另行禁用相关组件和短信操作。正常短信客户端保留 |
| 电台精灵品牌 | 包含最早开机图片的索引0与38、启动提示图和桌面标志；中间动画其他原厂帧按此前要求保留 |
| 8765急救 | 保留独立守护1.11.5；发行入口使用独立目录中的标记，不依赖管理APK首次创建数据目录 |
| 音量加Recovery入口 | 触发程序、校验脚本、开机入口及防循环标记合同均纳入；不改按键规则 |
| 特权命令串行处理 | 保留母机已验证的串行代理和原始程序；独立支持按当前机器实际应用UID建立本地权限，不套用母机UID |
| 防火墙 | 功能保留，但此开发版默认关闭，与当前母机一致；不再宣称开机默认启用 |

固件不包含用户账号、密码、短信、联系人、邮件、通话记录、Wi-Fi登录信息或设备身份分区。首次刷机会清空用户数据；用户所在时区、SIM、APN、漫游选项及SIP账号应由用户自行配置。

## 与母机有意不同的部分

- 发行镜像按既有精简清单物理移除18类原厂应用；母机中这些停用文件可能仍然存在。
- 母机运行时看到的是绑定后的Nexui、IMSCC及蜂窝标签APK；镜像需要保留可供首次扫描的原厂签名Nexui和IMSCC。取号占位包则从第一次扫描起就不申请短信权限。
- 发行系统模板改为正确应用页；母机的正确页面保存在数据区，系统模板仍是原厂版本。
- 新机多出初始化白名单及待执行标记，不能复制母机的“已经执行完”状态。最终复核补入了Zello省电白名单；母机本来已经设置，新包需要首次创建。
- 管理APK为已签名的1.11.5；母机旧管理应用保持停用，实际急救由独立守护运行。
- 发行独立守护不依赖管理APK私有目录。因此仅卸载管理APK不会关闭固件内置8765。开发结束需要关闭时，可通过已有命令客户端删除`/data/local/d31-rescue/enabled`；守护检测到标记消失后退出，下次开机也不会启动。独立系统支持和U盘功能不受影响。

## Windows工具1.6.4

只下载一个`D31-Flash-Tool-v1.6.4.exe`。ADB、首次引导/急救APK 1.11.5及aria2均内置，不需要测试文件或源码才能运行。固件ZIP单独下载，选择时保持ZIP格式，不要解压。

GitHub和Cloudflare两个下载按钮均指向1.4.1，并校验同一份大小与SHA-256。公开GitHub下载不需要Token；仍保留断点续传、多连接受限后降为单连接、速度、进度和剩余时间显示。

刷后验收增加首次初始化结果、独立存储服务、正确应用页名称及TCP设置。若原厂系统关闭adbd或临时改到其他端口，工具在安卓启动完成且8765可用时恢复D31的5555，再继续检查；不操作其他设备的ADB服务器。不能把“连上ADB”当作整包验收完成。

## 验证范围

已完成签名、最终载荷哈希、ext4一致性、安装器结构、应用签名及版本、缓存匹配和初始化失败重试测试。母机局部更新后普通重启约51.4秒完成桌面交接，观察到约395秒无新的桌面崩溃或无响应，SIP注册正常。

唯一母机没有执行清空用户数据的整包刷机。这个重启记录不能代替另一台D31的首次安装验收；本轮也没有重新进行U盘插拔、蜂窝通话、短信发送或收费流量测试。一直停在原厂桌面、外置存储打不开、反复黑屏或弹出无响应，均不属于正常验收结果，应保留工具日志和设备日志继续定位。

最终ZIP复核通过：2,331个system文件与母机逐字一致，4处内容差异为前述运行绑定、取号占位包和应用页模板；29个仅母机存在的文件属于已批准的18类精简应用。保留路径的属主、权限与全部符号链接无差异。

另外核对35项应用及功能载荷、8份编译缓存，以及母机boot和logo完整哈希；最终ZIP中的初始化类与两份XML在母机只执行`--inspect`和`--verify`，回读通过，未执行`--apply`。Windows工具18项实际后端模拟测试、启动后探针分支及最终EXE释放后端的母机只读准入通过。

## 音量加进入Recovery

要求设备已经安装该入口，并且内核仍能启动、system和data仍能读取。断电后按实正面音量加键，再接通电源，保持约30秒，然后松开等待。检测到按键后设备会再次重启进入Recovery；可能先短暂出现桌面。老设备按键接触不良时，要按实按钮内侧。

在Recovery中，音量减向下移动，短按免提确认。退出选择`reboot system now`。入口带防循环保护。此方法不是BootROM按键，不能保证修复引导器、内核或存储损坏。详见[Recovery入口和写入范围](D31-v1.4.0与Recovery入口.md#使用音量加键进入recovery)。Windows的卡刷功能仍为预留位置。

本包只写system、userdata和logo；写入前逐字核对boot基线，不写boot、Recovery或设备身份及校准分区。启动脚本保留原厂自身的Recovery校验与修复逻辑，不能将“安装器不写Recovery”误说成原厂系统永远不会修复Recovery。
