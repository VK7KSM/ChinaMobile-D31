### 清单字段

| 字段 | 合同含义 |
| --- | --- |
| `role` | 固定为`BOARD`、`FIRMWARE`或`TARGET`；比较时顺序必须对应 |
| `snapshotId` | 不可变清单引用，三方不得复用同一引用；不填写设备序列号 |
| `baselineId`、`baselineRevision`、`firmwareId` | 绑定开发板基准版本与指定固件版本；必须逐项匹配规则 |
| `build`、`collectorVersion` | 原始构建及采集器版本，保留在报告引用中；首批三方构建必须相同，跨构建对照需另定适用合同，否则为`BUILD_MISMATCH` |
| `capturedAtMs`、`validUntilMs`、`uptimeMs` | 非负整数毫秒；采集时刻不得在比较时刻之后；有效期和规则最大年龄均须满足，边界时刻包含在有效区间 |
| `context` | 明确列出`model`、`hardwareClass`、`firmwareFamily`、`stage`、`network`、`sim`、`storage`七个条件；三方及规则精确相同才准入 |
| `completeness` | `COMPLETE`或`PARTIAL`；声明完整却含不完整范围属于矛盾输入 |
| `scope` | 必须显式列出范围根路径、枚举状态、来源和缺口原因；不自动增加或排除`/data` |
| `entries` | 在既定范围内逐路径记录存在证据及字段证据；路径必须绝对、规范、唯一，不接受相对路径、点段、双斜杠、反斜杠或尾随斜杠 |

范围状态为`COMPLETE`、`PARTIAL`、`READ_FAILED`或`NOT_CHECKED`。除完整外均须填写`reason`；所有状态均须填写`source`。范围根不得重叠，`/system`不包含`/system-other`。三方和规则的范围集合不同时，保留各方范围原值并判为不可比较。

条目`presence`使用证据对象；`OBSERVED`时值只能为`PRESENT`或`ABSENT`。只有存在时才允许非空`fields`。父路径缺失而子路径存在属于矛盾清单。未列出的路径仅在对应范围完整枚举、整份清单声明完整时推断为`ABSENT`，保留枚举来源和推断原因；其余情况为未检查或读取失败。这样可以发现新文件、漏文件和额外旧副本，又不会把扫描中断当成文件消失。

### 字段证据

每个存在条目必须取得`type`、`sha256`、`mode`、`uid`、`gid`、`link`、`selinux`、`xattrs`、`activeSource`、`mountSource`和`activation`的证据，才能完成该条目核验。字段可以缺省以保留不完整输入，但比较时自动生成带来源的缺证据标记，绝不把三方同样缺字段算作相同。

证据对象包含`state`、`source`，以及观察值或缺口原因。状态如下：

| 状态 | 判定 |
| --- | --- |
| `OBSERVED` | 必须有非空值和来源；比较实际值，不比较证据文件名是否相同 |
| `NOT_APPLICABLE` | 必须有原因和来源，不携带值；只有类型证据及适用性合同允许时才作为已核验 |
| `READ_FAILED` | 读取失败，必须保留原因，不携带旧值冒充本次证据 |
| `NOT_CHECKED` | 尚未读取或证据字段缺省；相等判断为未知 |
| `UNSTABLE` | 持续变化或无法取得一致性快照；相等判断为未知 |
| `REDACTED` | 原值不可用于本次比较；必须去掉原值，不能让相同脱敏占位值判一致 |

`type`支持`file`、`directory`、`symlink`、`block`和`semantic`。`sha256`为64位小写十六进制，`mode`为四位八进制字符串，`uid/gid`为0至4294967295的整数。`xattrs`为键值字符串对象，逐键比较且不依赖JSON成员顺序；空对象是明确观察到无扩展属性，与字段缺省不同。其他标准值均为非空字符串。

`semantic.`前缀扩展字段用于配置结构、迁移状态、初始化阶段、证书摘要、组件启用、启动结果和分区版本等独立证据。值限字符串、布尔或整数，严格按类型比较，不把数字`1`和字符串`"1"`合并。三方任意一方列出的语义字段会进入并集，其余方缺失则判证据不足。本模块不自行解释数据库、挂载表或进程数据；一致性快照、语义归一化、证书取得和活动来源证明由后续采集适配器负责。

类型已证实不是软链接时，`link`允许显式不适用；目录或软链接的`sha256`允许显式不适用。其他不适用必须由规则逐路径、逐字段登记。文件和块设备哈希、软链接目标、非语义对象的权限/属主/SELinux标签不得通过适用性规则跳过。没有类型证据时，任何不适用都不能核验通过。

快照必须在进入本模块之前移除密钥、账号明文、消息、校准个人值和设备标识。仅比较结构、启用状态、已审核的非个人语义；需要原值才能比较但又不得保留时使用`REDACTED`。本模块不会识别任意字符串中的秘密，不承诺自动脱敏，也不会读取原始证据引用指向的文件或验证其真实性。

### 版本化差异规则

规则显式绑定`baselineId`、`baselineRevision`、`boardSnapshotId`、`firmwareId`、`firmwareSnapshotId`、上下文、范围及最大快照年龄。冻结引用的真实性和开发板已经过人工确认由上层负责；本模块不进行签名验证，也不自行认可开发板为正常状态。

`allowances`的每条规则包含唯一`id`、精确`path`、精确`field`、`reason`、`basis`以及逐项批准的`board/firmware/target`原始值。只有三方证据完整且该三元组精确命中才分类为允许差异；不能掩盖其他字段、相邻路径、不同原值或采集失败。不支持通配符、正则路径、目录排除或默认忽略`/data`。同一路径字段的重复规则、重复规则编号和互相冲突的规则拒绝。

`notApplicable`逐条列出`id/path/field/reason/basis`，仅放行适用性判定，不代表任意差异许可。所有命中的理由及依据进入字段报告；未使用规则编号进入`unusedRuleIds`，可发现陈旧或未覆盖规则。

### 报告解释

每条路径保留`presence`和全部字段的开发板、固件、目标原始证据，附三组成对结果、分类、差异类别、实际来源字段、影响和下一项只读建议。三方关系区分全部相等、仅目标不同、仅固件不同、仅开发板不同、全部不同及部分证据，不能据此直接命名为打包或安装根因。全部报告的`rootCause`固定为`NOT_ESTABLISHED`。

`counts.total`为本批已知路径并集大小，且始终等于`verified + unchecked + failed`。读取失败优先于未检查。`same`仅计完全核验且无差异的路径。`abnormal`、`allowed`是独立差异指标：同一路径可能一部分允许、一部分异常，也可能有已证实差异且另有读取失败，所以不可与前三项直接相加。字段报告始终保留这种混合事实。

范围有独立`scopeCounts`及逐范围三方证据。未列条目的boot/recovery等范围仍显示未检查或读取失败。`inventoryTotalKnown=false`表示枚举总量未知，不能把当前路径并集当全系统项目数。已确认不存在的一方无元数据可比，此时标记`presenceDependent`，仍保存存在方的全部元数据及其读取缺口。

`offlineComparison`可以是`MATCH_WITHIN_SCOPE`、`ALLOWED_DIFFERENCES`、`DIFFERENCES`、`INSUFFICIENT_EVIDENCE`或`NOT_COMPARABLE`。即使存在已证实的异常，其他证据不足时总结果仍是证据不足，异常计数和字段证据不消失。全空路径并集不产生空集一致结论。

所有成功生成的报告都明确写入`comparisonExtent=SINGLE_BOUNDED_BATCH`、`wholeSystemCoverage=NOT_ESTABLISHED`、`aggregationStatus=NOT_IMPLEMENTED`、`systemConsistency=NOT_ASSESSED`和`runtimeVerification=NOT_PERFORMED`。离线匹配不能称为整机一致、重启交接通过或业务正常。

### 容量及拒绝比较

4096是首批单份清单及三方路径并集的批次上限，不是完整D31文件树上限。另设32个范围、共2048条规则、每条48个字段、每字符串4096字符、每份输入累计8兆字符、60万个对象图节点和12层深度上限。序列化复制前先遍历检查，可拒绝循环引用、超长输入及控制字符；`xattrs`另限32个键。对完整JSON文本的解析前资源限制由CLI或其他输入层负责。

达到上限仍可比较，超过任何上限不截断、不抽样、不返回通过。单份超限为`INPUT_LIMIT`，三方并集或字段并集超限为`COMPARISON_LIMIT`。调用方捕获`DiagnosticContract.Invalid`后可保存`toJson()`返回的拒绝报告，其`offlineComparison=NOT_COMPARED`；未知项目总数和未检查数为JSON空值，已核验数为零，同时携带限额、错误码和后续聚合标记。父任务CLI可复用这个拒绝出口；未经处理直接抛出异常也必须作为未比较，不能记成功。
