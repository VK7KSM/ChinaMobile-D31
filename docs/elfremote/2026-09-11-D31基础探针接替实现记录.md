## 只读运行清单

预检直接读取父任务的`RemoteRuntimeInventory`输出，使用`schemaVersion=1`、`operation=runtime_inventory`、`capturedAtMs`，以及`installed/systemArchive/active`各自的`state/metadata`。`installation`统一读取`metadata`下的系统标志、更新系统标志、特权标志、应用权限等；已拒绝早先口头提议的`value`结构。

每份APK以实际原件元数据判断，系统原件来自固定系统路径；PM隐藏的系统登记版本不能替代它。读取失败不等于不存在，不将失败清单当作新机。`classification`描述所观察到的层次，`systemState`表示系统托管证据是否完整，两者含义不同。

| 输入状态 | 分类及允许的后续审查 |
| --- | --- |
| 普通基础APK，系统目录、标记、启动脚本和活动核心明确不存在 | `ORDINARY`，首次系统部署审查；不把普通覆盖安装当作已建立托管 |
| 安装副本在数据分区，系统原件可核验，PM有系统及系统更新标志 | `MANAGED_SYSTEM_UPDATE_OBSERVED`；标记、备份等未齐时仍可完成分类，但不得开启迁移门 |
| 已托管完整核心，系统基线至少85 | `MANUAL_FULL_HANDOFF_REVIEW`；兼容基线允许低于安装及活动版本 |
| 已托管且真实系统基线低于85 | `MANUAL_BOOTSTRAP_BASELINE_REVIEW`；需单独审查旧监督器接替条件 |
| 候选版本低于任何已观察版本，或同版本摘要不同 | 阻断降级或版本冲突；不使用卸载、降级或清数据绕过 |

85来源于`RemoteManualBootstrap.MIN_SUPERVISOR`，是既有监督器兼容门，不是新候选的固定版本。`RemoteManualUpdate.tick()`只接替比活动原件更新的完整APK；当前完整候选已安装且已选中时输出单独的健康复核路线，不重复安装。

`assessment.coreHealth=FRESH_SELF_REPORTED_MATCH`、`health`字段均不证明进程实际加载。预检不使用它们开启加载门；默认`loadedCore=NOT_CONFIRMED`。即使补充了独立加载证据，`deviceAccepted`及`adbHandshakeVerified`仍固定为假，本工具只给前置条件，不给真机最终验收。
