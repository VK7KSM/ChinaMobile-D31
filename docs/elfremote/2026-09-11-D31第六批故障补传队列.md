```powershell
node research/d31_adb_bootstrap/tools/fault-transfer/FaultTransferCli.mjs --state-dir $privateQueueDir --session $privateSessionPath --device-name $targetName --expected-version $expectedVersion --active-apk $activeApk --max-events 2 --max-ms 180000 --max-bytes 16777216 --max-requests 96 --max-index-pages 8 --max-retries 3
```

这些变量由主任务在私有验收环境提供；文档及源码不包含真实会话、设备标识或APK摘要。`expected-version`必须与Web实际`app_version`匹配。`active-apk`要求`/data/local/d31-remote/releases/<64位小写摘要>/remote.apk`，属于操作者明确提供的已核实活动路径；本工具不另行读取设备映射来证明该路径正在运行。

恢复时再次执行相同命令，必须使用同一队列目录、设备名、预期版本及活动APK路径。不得通过新建目录来掩盖未决任务。持久目录绑定Web设备号；名称重新绑定另一设备或目标参数变化均拒绝继续。私有session仅作为调用时参数读取，不保存到队列，不打印到终端。可用`--python`指定本机解释器。

```javascript
import {runRound} from './FaultTransferQueue.mjs';
import {QueueStore} from './QueueStore.mjs';
import {WebTransport} from './WebTransport.mjs';
import {PackageVerifier} from './PackageVerifier.mjs';

```

`runRound`另可注入`clock:{now,monotonic,sleep}`及同步故障注入`checkpoint(label,state)`。传输适配器提供`resolveTarget`、`queryTask`、`enqueue`、`metadata`、`download`，所有异步网络方法必须遵守传入`AbortSignal`；下载按回执长度流式写入指定全新文件。生产入口默认采用本批实际Web适配器，测试仅注入离线替身。

退出码：`0`为本轮正常结束或达到事件数预算；`2`为时间、字节、请求、索引或重试预算耗尽，以及暂时不可达；`1`为需人工检查的阻断或本机执行错误。`0`不表示全设备故障源完整，也不表示队列永久清空。标准输出仅给本轮计数和边界；事件号、阶段请求、回执、包和逐项验包结果留在私有目录。

### 持久化与恢复门

每一阶段在发送之前把完整请求、唯一任务号和原有效期同步落盘。每次恢复先查询原号，权威查询明确不存在且原有效期尚未结束时才同号同参数补交。网络错误、查询失败、任务运行中或结果未知均不创建替代任务号。任务过期、已知失败、截断或身份冲突保留证据并阻断；不自动重置该阶段。

状态采用带SHA-256的不可变顺序快照，通过全新临时文件、文件同步和重命名提交。最新已提交快照损坏即失败关闭，不回退旧状态重发。未提交临时文件和失败下载半件保留，不覆盖已有包。下载成功但状态落盘前中断时，按已持久化唯一文件名重新检查长度及摘要；匹配则直接继续验包。不匹配的中断半件可在下一有预算轮次重新下载同一`get_file`对象，不生成新的上传任务，不声称支持分块偏移续传。

本地并发锁复用Python标准库：Windows使用`msvcrt.locking`，其它宿主使用`fcntl.flock`。锁由独立子进程持有到主进程管道关闭，另一调用失败关闭；没有陈旧PID锁的自动猜测删除。文件内容同步在Windows已实现，但Node没有可移植的Windows目录同步接口；本批验证进程崩溃恢复，不声称突然断电或磁盘故障下目录元数据必然持久。

`VERIFY`实际运行既有Python逐项ZIP验包器，成功结果也同步落盘。`ARCHIVE`恢复及实际提交前重新检查本机原件长度、摘要和验包参数，只有完全绑定同一包的证明才调用`archive <eventId> <sha256> <bytes> <manifestSha256>`。服务器显示`uploaded`或`ready`均不足以授权归档。归档回执要求同包、`originalsDeleted:false`、`releasedBytes:0`、`activeSlotReleased:true`。随后独立`query`核对同一导出仍有效且`archived:true`，才进入`DONE`。

`PARTIAL/gaps`表示源证据不足，不表示冻结包传输失败。只要包逐项验证完整，就允许保全并确认归档以释放活动槽；源完整性原值和缺口保留在验包结果中。汇总始终给`fullIncidentWindow:false`、`rootCauseEstablished:false`、`originalsDeleted:false`，`preservedWithGaps`单列已保全但有源缺口的事件。

### 规模与节流边界

默认每轮最多2事件、16MiB下载尝试预算、180秒、96次网络调用、8页索引和3次可恢复错误。最大配置分别为3事件、24MiB、300秒、256次请求、32页索引和8次错误。默认每次请求最多20秒，任务查询间隔至少按持久化的1000毫秒门执行；失败指数退避默认最高10秒。下载尝试在开始前预扣整个回执长度，断网半件不会获得免费重试预算。

单包最多8MiB，Web JSON响应最多256KiB；根命令正文仍按16000字符门检查。本机队列默认256MiB容量、最多128个事件记录、4096份状态快照；达到任一上限失败关闭，不删除原件或静默丢弃已归档记录。目录需位于操作者保护的本地私有文件系统，不支持多个机器共享网络盘并发操作。容量耗尽或版本变更时需要主任务核对保全证据、未决任务和迁移方案，本批没有自动清理或人工重置指令。

旧索引按事件号游标扫描，不能假设按发生时间排序。跨轮保存游标；到达尾部后结束当轮，下轮从头扫描以发现游标之前新增的条目。有限页数不等于完整源发现；没有接入尚未冻结的`pending`新合同。
