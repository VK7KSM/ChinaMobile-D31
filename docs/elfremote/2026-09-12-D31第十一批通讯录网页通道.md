# 2026-09-12 D31第十一批通讯录网页通道

## 任务意图与范围

本批由D31通讯录子线实现LOCAL分页的宿主验收工具。目标是在正常管理员会话、设备管理连接和根维护恢复后，沿用已有生产`root_exec`任务通道，验证真实APP一次原号建立快照、逐页读取、首页复读、关闭及关闭后拒绝。每个步骤最多提交一次，失联后只查询持久保存的原任务编号。

源码权威目录为`research/d31_adb_bootstrap`。本批只新增`tools/Verify-RemoteContactsPagesWeb.mjs`、对应`.test.mjs`和本记录；不修改Android公共入口、网络、通讯录生产代码、共享Web、共享Gradle或既有传输工具。未连接真机、未访问生产Web、未构建APK、未推送。文中的生产验收命令由主线执行，本批离线通过不能冒充真机通过或网页通讯录列表已经实现。

依据为第十批通讯录分页专项、`Verify-RemoteContactsPage.mjs`及其严格回执验证器、`fault-transfer/WebTransport.mjs`、`QueueStore.mjs`、`FaultTransferQueue.mjs`、正常登录会话合同，以及现有服务端普通任务路由和Android根命令回执封装。

## 实际接口与身份门

| 接口 | 用途 |
| --- | --- |
| `GET /api/devices` | 沿用唯一设备名称、`mdl_d31`、`ready`、精确`app_version`、`managed_file_return`门，另外核对同一设备的`managed_exec_tasks=true`。 |
| `GET /api/elfremote/tasks?device_id=...&task_id=...` | 每步先查询原编号；仅既有明确的未找到任务响应视为不存在。 |
| `GET /api/elfremote/tasks?device_id=...` | 首次提交前检查普通任务忙槽；不取消或覆盖其他任务。 |
| `POST /api/elfremote/task` | 提交既有`root_exec`，字段为`device_id`、`id`、`type`、`params`及`expires_at`。 |

`params`固定`cwd=/`、`timeout=20`，命令仅执行身份预检或冻结`ContactsPageCommand`入口。任务编号使用随机UUID，APP建立快照的操作编号独立生成并首先持久保存；没有新造分页服务器路由。

首次根预检要求UID 0、API23、已确认的D31设备及型号、Android 6.0构建指纹、有效boot编号、`active.json`的包名/版本/路径/摘要，以及活动APK与安装APK实际摘要一致。所有内容命令前再次检查同一boot。最后重新执行身份预检。版本号必须大于128，实际是否支持分页仍以真实APP回执为准。

每条命令包裹独立随机末尾退出标记。回执必须匹配原任务编号、`root_exec`类型、原到期时间、完整末尾标记、退出码及`stage=command/action=completed`。`truncated`必须为`false`，文本不得超过16000字符。服务端没有返回完整原请求摘要，本工具以持久原意图、随机编号、期限和命令标记共同绑定结果，不宣称得到了服务器未提供的请求摘要。

## 分页与释放合同

1. 使用`ContactsPageCommand open <摘要> <原操作编号>`。仅接受`kind=NEXUI_APP_LOCAL_METADATA`、`operation=read_local_pages`及匹配的`app_operation.operation=read-local-pages`。
2. 复用第十批严格验证：清理回执必须真实匹配请求、APP摘要、boot，且为`RELEASED`及`MATCHED_RELEASE_RECEIPT`。metadata或其他operation不能借用为pages释放凭据；校验失败不自动执行恢复或释放未知占位。
3. 每次`page <摘要> <快照编号> <offset> 1`固定只取一条，按实际`next_offset`推进。每页校验LOCAL来源、同一快照、总数、边界、结束和内容标识，不重新采集全量。
4. 完整读完后复读首页，必须与第一份内容结构完全相同。
5. `close <摘要> <快照编号>`必须确认匹配快照已关闭。随后再次读取旧游标，必须exit 1且`CONTACTS_SNAPSHOT_GONE`。这最后一步在普通任务层显示`failed`是预期拒绝，不是发送失败。
6. 出错后仅在已取得有效快照描述且所有已提交步骤均有终态时尝试关闭。未知任务不会被`close`抢占；缓存到期不能假装验证了显式关闭。错误操作回执不会触发猜测性恢复。

APP仍为一次完整原厂回复的不可变内存快照，固定120秒，不跨进程死亡、升级或重启。宿主以open提交前时间作保守锚点，只在前100秒允许新增内容读取或首页复读，留20秒余量；查询忙槽后、实际提交前再次检查期限。缓存不是原厂数据库事务快照，仍保留`NOT_PROVIDED_BY_VENDOR`与`all_sources_complete=false`。

## 原号恢复与退避

复用`QueueStore`内核锁、带摘要的追加状态快照及独立私有回执文件。流程意图先落盘，提交前再持久保存`submitted=true`，然后才发POST。每阶段最多一次POST；即使崩溃发生在这次落盘后、真实发送前，也不能根据404猜测允许补发。

同一`--state-dir`重跑会验证目标、原请求、回执摘要并恢复查询。提交超时、断网、任务仍运行或回执未知时，不换号重开、不自动重新采集、不取消其他任务。明确不存在但已有提交意图的情况保持`CONTACTS_WEB_SUBMISSION_UNKNOWN`，由主线核对实际原号；不能删目录重跑来绕过未知任务。

主线共享`WebTransport`透传的可重试`QueueError.retryAt`为绝对毫秒。本工具在捕获时写入持久`state.retryAt`，取现有期限、服务器期限及本地最小轮询间隔的最大值。重跑未到期时返回`CONTACTS_WEB_RETRY_BACKOFF`，连设备列表请求也不发；进程退出不会丢失退避。无有效服务器期限的网络错误至少退避一个轮询间隔。

到期后仍先查询原任务，不能因退避结束而重新POST。若退避耗尽120秒快照期限，只处理原号终态并尽可能关闭，不补内容页或二次open。宿主时钟倒退令该轮快照期限失效，禁止用倒退延长读取窗口。

默认单次运行90秒、96次请求、每秒轮询、每请求10秒；默认最多16页。可显式调整`--max-ms`至180000、`--max-pages`至64，页长始终为1。时间、请求、忙槽或网络限制导致暂停时，原目录可继续查询；页数或快照期限不足则明确失败，不能把部分列表作为完整成功。空或单条列表可验证闭环，但`crossPageExercised=false`，不宣称跨页已测。

## 私有证据与限制

宿主状态和原始响应存入调用者指定的私有目录，内容回执文件名带`private`，状态引用保存其SHA-256。控制台和摘要仅输出固定错误码、LOCAL来源、条数、页数和布尔验收状态，不输出姓名、号码、快照编号、设备名称、设备编号、会话或APK摘要。原始证据目录不能进入公开源码、发布制品或公共日志。Windows目录访问权限由主线选择的私有目录及现有ACL保证，不能把POSIX创建模式当作Windows ACL已设置的证明。

实际`root_exec`会将内容放入既有管理员任务结果，服务端按既有任务历史策略留存。因此“仅私有文件”在宿主侧成立，不能声称数据不经过服务端或只存在本机。没有发现本工具可使用的逐任务历史删除接口，本批不臆造删除路由。若要求服务端完全不保存个人内容，需要另行约定私有文件返回/删除合同；本工具不能满足这种更严格要求。

当前接口有16000字符根命令结果限制，固定一条减少截断风险，最终仍检查真实截断位与内容长度。任务通道是串行忙槽，120秒内可完成的条数取决于实际网络及设备耗时，本工具不承诺遍历4096条大列表。管理未就绪、会话失效、快照进程死亡或未知维护占位均明确停止，不借ADB绕过。

本批只证明普通网页命令通道的验证能力；没有开发网页通讯录列表控件、其他通讯录来源、联系人写入或跨boot快照。摘要固定`webContactsListDeveloped=false`、`adbUsed=false`。

### 第一次：身份预检输出粘行

主线报告首次真实Web验收原件为`b11-contacts-web`：身份预检返回`CONTACTS_WEB_DEVICE_IDENTITY`，尚未建立快照。原因是实际`active.json`没有末尾换行，`cat`输出与随后`busybox sha256sum`合并到同一行。初版人工拼接响应夹具始终有换行，因此漏过该问题。
