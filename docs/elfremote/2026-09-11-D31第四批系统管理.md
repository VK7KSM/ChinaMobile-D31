## 已核实的协议依据

- `research/FreePBX_VPNnode_Web/system-settings.js`中的`systemSettingsParams`是实际参数规范；任务类型为`system_config`，参数为`group/action/package/offset/key/value`，读取默认`action=read`。本批接受其已实现子集，不发明新任务名。
- 同文件`applySystemSettingsResult`要求回执`exit_code=0`、`action=completed`、未截断；`text`必须能解析为JSON，顶层`group`匹配请求、`sampled_at`为数值，写入还要求`applied=true`。回读内容直接放在顶层，不增加互斥的`settings`包装。
- D22的`ReportService.runCoreCommand`和`SystemSettings`提供了读取、修改、回读、失败恢复的已有业务合同。D22使用系统`settings --user 0`处理设置存储，并非只用普通`ContentResolver`。本批复用这一方式，但使用API23可用的进程退出轮询和有界输出，未复制API26的`Process.waitFor(timeout, unit)`。
- D22网络写入还依赖特权Wi-Fi配置原像、独立恢复守护、恢复记录及管理链路确认。这些条件尚未完成D31接线和设备验收，因此本批拒绝网络写入，不把异常分支模型冒称完整失联恢复功能。

## 冻结接口

入口为`net.elfradio.d31bootstrap.management.SystemManagement`：

```java
boolean supports(String type)
JSONObject validate(String type, JSONObject params) throws Exception
JSONObject execute(Context context, String type, JSONObject params) throws Exception
JSONObject execute(Context context, String type, JSONObject params, Control control) throws Exception
JSONObject capabilities() throws Exception
JSONObject readiness(Context context) throws Exception
```

- `supports`只对`system_config`返回真。`validate`返回规范化参数；不接受把字符串强转成布尔值、整数等宽松输入。不支持的键及网络写入在接触系统服务前抛异常。
- 成功返回真实快照，含`group`、`sampled_at`、`ok=true`；只有写入及回读相符才添加`applied=true`。读取不添加该字段。输出超过15000字符则失败，不截断后宣称成功。
- `Control.check()`供公共层检查取消；`Control.before(JSONObject)`在首次修改前保存`params/original/snapshot`。落盘失败即不开始修改。主任务应始终使用有`Control`的重载；无`Control`重载仅保留内存原值，不能作为生产原像持久化入口。
- 执行层不取得维护锁。公共层必须在执行全过程及失败恢复期间持有现有维护锁，并检查修复/Windows维护预留；不能仅在入队时持锁。
- 修改失败抛`SystemManagement.Failure`，其公开`result`包含`ok=false`、`applied=false`、`change_attempted`、`restored`、`recovery_required`及异常类型。公共层应保存该结果并返回非零退出码；不能把它当作成功快照。原始异常保留在异常链，业务结果不输出可能带私有信息的异常消息。
- 坏参数或明确不支持项可能在进入执行前抛普通异常，公共任务层应形成拒绝或失败回执，而不是无限重试或宣称执行成功。
- `capabilities()`只声明代码范围，`network_write=false`、`contacts=false`、`write_verified=false`。`readiness(context)`仅读取基础设置和应用身份；`ready=true`表示API23独立root上下文通过读取门，不能证明所有写权限及业务效果。建议主任务缓存此读取结果，并结合自身完整载荷、维护及公共入口就绪条件决定`managed_system_settings`，不要每次报告重复启动多条设置查询。

应用清单保留`offset/total/next`。指定包增加`components_total/components_next`和`permissions_total/permissions_next`；继续使用同一`offset`读取后续页。现有Web没有因此自动获得新的组件编辑页面。组件`enabled_state`为PackageManager原始状态，`enabled`综合应用和组件状态；`kind`为框架信息类型，其中接收器与活动均为`ActivityInfo`，不能据此区分两者。

原设置缺失时保留空值语义，不补造系统默认值。应用恢复保留原始0、1、2、3、4状态，而非统一`disable`。停用管理自身或系统共享身份应用会在原值采集阶段拒绝。音量使用设备实际最大值再次校验，Web的0..255范围不等于设备支持范围。

## 运行与恢复边界

1. 设置存储通过独立`/system/bin/settings --user 0`参数数组读取或写入，不经shell拼接。单次最长5秒、合并输出最多4096字节；实际进程非零退出、异常输出、超时、输出超限均失败。空原值恢复使用`delete`并重新读取，不写入猜测的默认数值。
2. 系统字体和语言读取使用API23的`ActivityManagerNative.getDefault`、`IActivityManager.getConfiguration`及`Configuration.locale`；不使用API24的`LocaleList/getLocales`，也不把新建root进程的资源默认值当作系统当前配置。隐藏接口仍须由主任务在D31验证。
3. 普通写入在调用前就标为“可能改变”，覆盖服务先改变再抛异常的情形。异常、回读不符、取消及结果超限均尝试恢复并核验原值；实际线程中断标志会在恢复期间临时清除，随后恢复该标志。恢复失败明确返回`recovery_required=true`。
4. 这不是跨进程强杀、掉电或恶意并发的完整事务文件系统。强制终止、Binder不可中断、超时后服务仍处理请求、设置服务自行变化等情形，可能需要查询保留原像并人工核对。网络写入没有依赖这种有限恢复保证而开放。
5. 网络查询只读，不探测服务器、不扫描无线网、不切换默认路由，不序列化Wi-Fi密码或查询联系人内容。查询异常写入`unavailable`，未知蜂窝开关或热点过渡态不会补成`false`。某些厂商接口可能拒绝root调用，未自动切换进程UID绕过权限；须由主任务验证真实调用身份。
6. 未增加运行时依赖。生产仅使用Android与既有`org.json`；测试使用本机已有JUnit、JSON、Android SDK、JDK、Node和PowerShell，没有下载依赖。
