## 入口与回执合同

```java
bridge.captureLocalAudio(String verifiedApkSha256,
                         String diagnosticId,
                         int durationMs,
                         AppMediaBridge.Callback callback);
// 回调继续使用既有签名：
void completed(JSONObject result);
void failed(String code);
```

本地Binder操作名为 `local_audio_capture`，参数为 `apk_sha256/diagnostic_id/duration_ms`。摘要必须是64位小写十六进制；诊断编号匹配 `[A-Za-z0-9_-]{1,96}`；时长必须是JSON整数1至5000毫秒，拒绝字符串、小数、空值及越界值。该操作不是新Web任务，主任务通过现有 `root_exec` 接入 `local_audio_capture <sha> <diagnosticId> <durationMs>`。首次设备验收计划2500毫秒，本线没有执行。

已只读核对主任务的 `RemoteMediaCommand` 调用：方法名、四参数入口和20秒外层等待兼容，活动APK与维护门仍由公共入口负责。根命令本身成功返回不等于采音成功，应读取内部 `result.state` 及释放证据。

| 回执字段 | 含义与验收边界 |
| --- | --- |
| `schemaVersion/operation/diagnostic_id` | 固定版本1、本地诊断操作、原始诊断编号 |
| `state` | 最终为 `COMPLETED/FAILED/CANCELLED/TIMED_OUT/RELEASE_UNCONFIRMED`；执行中还可观察 `PENDING/PREPARING/READING` |
| `app_pid/app_uid/audio_session_id` | 真实APP进程及AudioRecord会话归属；只用于私有原生元数据比对，不抄入公开文档。未取得会话编号时为-1 |
| `sample_rate_hz/channels/encoding` | 固定16000、1、`PCM_16BIT`；输入源为MIC |
| `bytes_read/frames_read/frame_definition/read_calls` | 实际读取字节、单声道PCM样本帧、`MONO_PCM_SAMPLE`、读取调用次数；一帧2字节，不是20毫秒编码帧 |
| `initial_record_state/initialized/recording_started` | 实际初始化状态、是否为已初始化、启动后是否处于录音状态；不是仅构造成功的推断 |
| `read_error/error_code/stop_error/release_error` | 原始负读取错误码及脱敏错误类型；没有读取错误时为0。异常原文不返回，防止携带私有路径或数据 |
| `record_state_after_release/recording_state_after_release` | 调用释放后的实际状态；未知为-1，预期分别为0和1 |
| `release_completed/release_verified/stop_completed/worker_finished` | 分别表示释放调用返回、释放后状态及工作完成核验、停止步骤完成、采集工作完成；不能只凭其中单个布尔验收 |
| `started_elapsed_ms/capture_started_elapsed_ms/finished_elapsed_ms/duration_deadline_reached` | 诊断开始、启动录音前、释放流程结束的单调时间及独立时长截止是否触发 |
| `preflight` | 创建前APP权限、AppOps和三来源缓存证据；占用快照路径为 `result.preflight.audio_occupancy_snapshot` |
| `managed_media/audio_persisted/network_started` | 恒为false；不开放持续媒体，不保存音频，不启动媒体网络 |

无活动会话时 `query("")` 顶层继续为 `state=idle/managed_media=false`；最近诊断保存在 `last_diagnostic`，不是把顶层idle改成诊断终态。诊断执行或资源释放未确认期间顶层为 `diagnosing`。可用具体诊断编号查询快照，或通过已有 `stop(diagnosticId)` 取消；同进程内已使用的编号禁止再次采集，延迟到达的旧取消请求不停止另一编号的诊断。

## 前置门、执行与退出

1. APP侧先核验API23、32位、实际应用身份及框架sourceDir的APK摘要。诊断直接使用系统AudioRecord，无需重复加载WebRTC JNI，没有新增外部依赖。
2. 在采集工作线程等待既有占用首采最多1500毫秒，要求真实APP权限GRANTED、框架包匹配、AppOps ALLOWED以及蜂窝、Nexui、其它音频三来源均IDLE；任一未知或失败均不创建AudioRecord。
3. 固定PCM16单声道16000Hz，系统最小缓冲大小需有效且不超过256KiB，实际采用至少1280字节。使用API23的非阻塞读取，每次最多320个采样；零数据时等待5毫秒。累计帧数不得超过时长对应的样本上限，且独立时长截止最多5000毫秒。样本每次读取后及最终退出均置零，没有音频输出接口、文件、摘要、波形或网络发送。
4. 录音期间蜂窝和Nexui缓存首轮立即检查，之后每100毫秒检查一次；BUSY或UNKNOWN即终止。这是缓存检查节拍，不是硬件变化100毫秒内必被发现：底层源仍按Newton约2秒刷新，超龄会转未知。全局音频不能区分自身与其它客户，诊断期间不把自身BUSY解释成独占证明，也不更改持续媒体的全局否决规则。
5. 握手及所有旧操作仍严格限制6秒。只有通过UID、操作名与参数检查的本次诊断才采用10秒总回执窗口；请求排队不重新起算。诊断内部执行上限8秒，同时从回执截止预留750毫秒用于等待释放。读取时长另有独立截止，避免厂商读取卡住后一直等到8秒。正常时长截止只取消诊断内部工作，不污染外层Binder请求取消标记，因此可以返回最终诊断回执。
6. root owner Binder死亡、桥取消、单独stop及Service销毁均触发诊断取消。停止仅发起一次，停止未完成时采集线程不并发release；真实Android适配的start/stop/release还通过同一对象锁串行化。start在锁内重新检查取消，取消先到时不迟到启动录音。
7. 无法确认停止或释放时返回 `RELEASE_UNCONFIRMED`，保留进程内占用，拒绝再次诊断或媒体会话。释放调用虽返回但实际状态不是0/1，也不放行复采。对于厂商原生构造、启动、停止或释放永久卡死，Java不能证明硬件已释放；回执等待仍有截止，迟到构造返回后立即清理且不启动。本批不通过杀APP进程、重启核心或更改音频路由掩盖此类失败。
