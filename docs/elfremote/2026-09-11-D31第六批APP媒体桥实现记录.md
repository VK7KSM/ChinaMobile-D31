## 公开接口与公共接线

```java
AppMediaService.configure(GuardFactory factory, URI trustedControlOrigin);
// GuardFactory的方法：
AudioGuard create(Context context) throws Exception;

AppMediaBridge bridge = new AppMediaBridge(rootSystemContext);
bridge.prepare(verifiedApkSha256, callback);
bridge.start(verifiedApkSha256, offer, callback);
bridge.stop(sessionId, callback);
bridge.query(sessionId, callback);
bridge.close();
// Callback的方法：
void completed(JSONObject result);
void failed(String code);
```

`configure` 只登记配置，不构造guard、不读取状态或加载JNI。主任务的 `RemoteApplication.onCreate` 登记 `context -> new AndroidAudioOccupancy(context).start()` 与生产控制源，符合此约定。服务位于正常APP进程，使用已安装APK的32位ABI；不改变64位root核心架构。Manifest中的应用类及非导出 `AppMediaService` 由主任务接入，不增加开机服务。

已只读核对 `RemoteMediaCommand`：回调签名正确；外层20秒覆盖桥内部6秒窗口；`query("")` 只查当前会话、不续租；只调用prepare/query的Bridge退出不会停止其它Bridge拥有的会话。公共入口以维护锁和活动APK摘要为门，不暴露start；APP另用自身 `sourceDir` 核验同一摘要，活动核心与已安装APP不一致时明确拒绝，不借root私有APK冒充APP身份。

`close()` 无受检异常，取消未回执请求，异步停止该Bridge已启动的会话。会话由root owner Binder关联；owner死亡取消其会话。具体会话编号且同一owner的query可续租，空编号和其它owner查询不续租。不同任务可用确切会话编号stop，不依赖旧任务占用普通执行槽。

## 身份、生命周期与准备回执

- AMS握手精确复用已证明的API23五参数 `startService(IApplicationThread, Intent, String, String, int)`，root的 `callingPackage` 为字符串空值。Intent只携带请求关联数据与回调，不携带媒体鉴权命令。
- 真正命令在APP Binder核验实际调用UID为root后执行；root回调核验实际APP调用UID、请求编号、启动标识、单调时间与16KiB上限。prepare/start走工作线程，stop/query不排在JNI准备后面。
- `prepare` 核验API23、真实APP32身份、APK摘要、RECORD_AUDIO权限、框架包名与AppOps，然后只准备JNI与占用证据。不构造AudioRecord、不连接网络；JNI准备会使用APP私有缓存解压并加载库，不能称为零文件写入。
- 为修正首采尚未完成而服务已退出的问题，仅prepare工作线程对 `AndroidAudioOccupancy` 调用 `awaitFirstSample(1500)`，随后 `cancel.check()`，再读取 `MediaReadiness.snapshot` 与 `result.audio_occupancy_snapshot`。不在onCreate等待，不循环等待IDLE；首轮成功或失败均可结束等待，超时仍返回真实未知证据。该返回值不用于推断空闲。
- `result.audio_occupancy_snapshot` 直接使用Newton脱敏缓存快照，包含三来源分类、原因、采样起止时间、年龄、范围与非原子占用声明。权限或来源失败仍为UNKNOWN；没有guard为 `GUARD_UNAVAILABLE`。相邻两次缓存读取可能跨过后台刷新，不能把不同采样时刻混为一次原子快照。
- `preconditions_satisfied` 仅表明本次准备条件观察；`PREPARED_WITH_GAPS` 保留缺口。无论结果如何，`audio_record_created=false/network_started=false/managed_media=false`，不宣称采音、音频路由或WebRTC连通。
- 服务采用 `START_NOT_STICKY`，无请求和活动会话时结束；`onDestroy` 取消任务、停止会话、关闭工作线程，并调用backend.close关闭实现AutoCloseable的guard。关闭操作有离线幂等断言，真实服务退出和采样线程终止由主任务验收。
- 会话15秒owner租约兜底停止，连接取消直接关闭正在连接的Socket。原生JNI或DNS调用不保证可被Java立即中断；无法确认原生资源释放时保守保留 `release_unconfirmed`，不宣称有界物理释放已被真机证明。
