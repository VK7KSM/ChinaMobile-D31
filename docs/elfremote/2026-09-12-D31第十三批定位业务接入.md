## 2026-09-12 代码接入与边界

本条记录定位子任务的实现和离线结果。范围仅为 `research/d31_adb_bootstrap` 下的 `telemetry`、`RemoteTelemetry.java` 及对应测试。本子任务没有操作真机、运行共享 Gradle、修改版本、修改共享 Web 或调用 Google 定位服务。Manifest、核心正式接线和设备定位开关由主线统一处理。

### 已实现

- 保留原 `AppLocationCache` 的真实 AMS 启动和 Binder 发送 UID 验证；主动定位、Wi-Fi 扫描和小区查询都在不导出的 `LocationCacheService` 所属应用 UID 中执行。没有借用系统包名或将 root 冒充应用。
- 扩展定位桥的 `location_window_ms`，零值仍为缓存读取；主动采样窗口上限为45秒，桥回包预算为窗口加4秒。应用入口仍要求请求在4秒内启动，不能将扩大的采样预算用于重放旧请求。
- 主动定位监听 GPS 和系统网络提供者；存在 GPS 时，不因先到的网络点立即结束搜星。30秒内的新鲜 GPS 可复用，其余情况真正注册监听；获得 GPS、到期或取消后移除监听。清理失败后，本应用进程不再建立新监听。
- 新增 `RemoteLocationRadio`，复用 D22 `RadioLocation.java` 的观测方式及生产 `google-geolocation.js` 的字段合同。正式字段为 `radio`，不是 `radio_location`。
- Wi-Fi 至少两个不同的有效接入点才进入定位数据，最多保留最强六个；过滤本地、组播、保留 BSSID、非法信号值和过期扫描。不采集 SSID、设备 MAC、IMSI 或账号。只在 Wi-Fi 已开启且缺少新鲜扫描时请求扫描，不修改 Wi-Fi、移动数据或定位开关。
- 小区支持 `gsm`、`wcdma`、`lte`，优先实际注册小区，单次只保留一种制式，最多四个有效小区。没有小区数据时不依赖插卡状态构造数据。D22 对注册小区零时间戳的特例没有直接移植到 D31；D31 还没有相同证据，零时间戳暂按无法证明新鲜处理。
- 无线观测最多接受两分钟内的数据。`sampled_at_ms` 从有效观测的单调时钟时间换算，采用其中最旧时间；读取缓存、回包、补发和报告合并均不刷新采样时间。时钟跳变或过期数据被排除。
- 新增独立 `RemoteLocationSampler`：先返回无线观测及缓存，再执行主动 GPS；结果随到随通知。单线程、同轮单任务，正常每轮最多通知两次，下一轮至少间隔五分钟。GPS 等待不占报告或健康线程。

### 主线冻结接线接口

`RemoteTelemetry` 提供以下同包接口；主线直接调用，无需增加新组件：

```java
telemetry.enableLocation(context(), () -> {
    // 在此仅置位“需要新报告”并唤醒核心，不同步调用网络或生成报告。
});

// 放在bootComplete()之后的正常tick路径，每次调用均不等待定位。
telemetry.tickLocation();

// 原有enrich调用不变，会合并已有定位与radio。
body = telemetry.enrich(body, existingCollector, 250);

// 原有close会同时取消定位任务。
telemetry.close();
```

初始化只做一次，不要在每次报告重新创建 `RemoteTelemetry`。回调发生在后台线程，主线使用已有线程安全通知方式，并明确将下一个新报告设为立即到期；只唤醒而仍等待原十五分钟截止时间不算完成接线。已经冻结的待确认报告原样重传，定位通知保留至随后创建新报告。通知和报告不能重置定位五分钟节流时间。`enrich` 不触发新的 GPS 任务，也不调用无线扫描。

- 沿用不导出的 `.telemetry.LocationCacheService`，无需新增 Manifest 组件或开机 Receiver。
- 当前已知 `location_mode=0` 与 `location_providers_allowed=gps` 不一致。只有主线在候选准备完成、保存设置原像后统一开启定位并验收；代码不自动修改用户开关，不增加同步开机脚本。

## 2026-09-12 23:15 缓存诊断快照接线

返回字段固定为：顶层 `location_reason`、`gpsPresent`、`radio`；其中 `radio` 包含 `sampled_at_ms`、`wifi_reason`、`cell_reason`、`wifi_count`、`cell_count`、`usable`。数量为当前报告可用的接入点及小区数；无线观测过期或时钟异常时数量为零、`usable=false`，但保留原采样时间和原观测原因供排查。尚未采样时原因是 `not_sampled`、时间为空。`gpsPresent` 表示现有报告合同的 `gps` 坐标字段当前有效，不单独证明卫星定位成功。

快照只返回白名单状态，不含坐标、BSSID、MAC、小区ID或完整无线数组；外部修改返回对象不会改变采样缓存。正式网络开关及五分钟采样节流保持不变。写盘由主线完成，本子任务未改 `tickBusiness` 或状态文件写入代码。

| 字段 | 含义 |
| --- | --- |
| `wifi_initial_raw_count` | 本轮开始时扫描缓存原始条目数 |
| `wifi_initial_valid_count` | 本轮开始时通过时间、MAC、信号强度及去重的AP数量 |
| `wifi_raw_count` | 本轮最后读取的扫描缓存原始条目数 |
