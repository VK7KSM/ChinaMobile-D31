# D31第三批系统修复执行器

## 2026-09-11：生产文件平台交付

本批在既有`repair`事务核心上增加真实Android 23 root文件实现，保持方案、去重、持久日志和显式推进合同。交付的是受控静态文件的磁盘状态修复，不是运行组件升级或重启生效验收。未连接设备、未运行Gradle、未修改共享入口、构建、版本或Web；组合构建与设备验证由主任务执行。

### 公共接口与固定范围

```java
new AndroidRepairPlatform(
    File journalRoot, File payloadRoot, RepairPlan plan,
    AndroidRepairPlatform.LeaseProvider leases, String approvedDigest
)
```

`LeaseProvider.acquire(String taskId)`返回`RepairPlatform.Lease`，占用时返回`null`。Command已全程持有`RemoteMaintenance`时，可以传入`taskId -> () -> {}`；平台没有另建维护锁路径。原`RepairJournal`的`transaction.lock`继续仅保护事务日志，不替代跨业务互斥。

`approvedDigest`必须来自明确请求且等于完整方案摘要。日志根、载荷根和目标目录不能重叠。主任务约定载荷根固定为`/data/local/d31-remote/repair-input/<task>/artifacts`，平台只读取其中由`change.artifact`标识的本地文件；不接受URL、命令文本或请求中的物理目标映射。

`productionPaths()`返回不可变编译期映射：

| 逻辑路径 | 真实目标 | 本批验证范围 |
| --- | --- | --- |
| `system-support/start.sh` | `/data/local/d31-system-support/start.sh` | 已有普通文件的内容与支持的元数据 |

`guard`未开放。修改正在运行守护对应的磁盘文件不能证明进程已经加载新inode，本批没有新增重载。`start.sh`替换完成也不立即执行脚本；回执应使用`FILE_STATE_VERIFIED`及`runtime_effect=NOT_CHECKED`，实际启动效果需要独立授权的重启验证。生产平台不访问分区、账号、身份、校准或更新载荷目录。

### 文件实现

新增`AndroidRepairFileIo`使用`android.system.Os`与固定目录描述符完成打开、复制、同步和改名，不调用shell或BusyBox。每层祖先先核对类型和属主，再以`O_NOFOLLOW | O_NONBLOCK`打开并核对inode；文件只接受有限长度、单硬链接、非特殊权限的普通文件。目录或链接不会当作目标文件读取或替换。

一般祖先要求root持有且组和其他用户不能写入。仅固定祖先`/data`接受主任务只读现场确认的`1000:1000 / 0771`；不会把这个例外扩展到任意目录。主任务提供的现场同时确认`/data/local`为`0:0 / 0751`，`d31-remote`和`d31-system-support`为`0:0 / 0700`。修复日志私有根及新元数据目录要求`0:0 / 0700`，不通过静默chmod掩盖不符合要求的已有目录。

复制前后均核对文件摘要、字节数、inode及支持的元数据，读取和复制有64MiB上限并响应线程取消。替换文件以唯一临时名排他创建在目标同目录，完整复制、设置原像元数据、同步文件、再次核对原像后才执行一次原子改名并同步父目录。失败临时件保留，不复用或清理旧证据。

检查和改名窗口依赖主任务提供的全局维护租约。描述符固定路径身份，但不是内核提供的通用比较交换；不合作的root写入者不在该互斥合同内。本批没有扩大为任意目录写入平台。

### 元数据与中断恢复

原像记录位于`<journalRoot>/<task>/metadata/<index>.json`，保存原像内容摘要、字节数、inode身份、属主、组、权限、修改时间和SELinux标签，并绑定方案摘要与逻辑路径。记录包含原始快照文本摘要；不使用新的现场值替代已有原像记录。

元数据记录先写新临时文件并同步，以排他硬链接提交完整记录后删除临时链接、同步父目录。中断遗留的原件不覆盖。记录损坏、缺失、来源方案不符或原像发生变化时停止目标改写。

受支持的保留项目是UID、GID、普通权限位、秒精度修改时间、SELinux标签。拒绝特殊权限、文件能力和访问ACL，祖先目录不能向新文件继承默认ACL。Android 23没有公开的扩展属性枚举接口，本批不承诺保留任意自定义扩展属性；也不把读取会改变的访问时间、内核维护的状态变更时间或新文件inode登记为可保持项目。

Android 6.0.1源码已核对隐藏接口：

```java
libcore.io.Os.getxattr(String path, String name, byte[] value) // 返回int长度
libcore.io.Os.setxattr(String path, String name, byte[] value, int flags)
```

实现从`libcore.io.Libcore.os`取得平台对象，使用这两个反射方法；不误用API26才公开的`android.system.Os.getxattr`。原始标签通过固定文件描述符路径读取和设置，标签缺失或无法确认即拒绝，不以默认标签猜测。该签名已通过AOSP源码核对和独立编译，真实设备调用结果等待主任务隔离测试。

前向切换要求内容及元数据仍与持久原像相符。备份副本用于恢复内容，原像记录用于恢复元数据。回滚即使原载荷目录已被移除也可继续核验备份，不把可选载荷存在性作为恢复前置条件。

原核心增加向后兼容的`RepairPlatform.verifyRestored(Change)`默认方法，生产平台实现内容和元数据回读。回滚路径在“原像内容已经存在”、回滚意图重开及最终恢复检查处调用它；内容正确而权限或标签错误时为`NEEDS_ATTENTION`，不误报恢复成功，也不重复写入。

新文件操作对内容和父目录执行同步；既有事务日志仍沿用原持久化机制。本批测试验证异常及模拟进程中断，不据此宣称真实断电后的全部文件系统和日志持久性已验收。

## 2026-09-11：首次Android隔离测试失败后的修正

### 原始观察

主任务首次设备测试原件位于`research/d31/captures/2026-09-11/parallel-batch3-io-a/after-private.txt`，第1065行起记录`getxattr failed: ENOTSUP`，调用链为`libcore.io.Posix.getxattr`、`AndroidRepairFileIo.openDirectory`、`directory`、`parent`、`privateDirectory`及fixture初始化。主任务确认尚未创建本次fixture根，也没有改变既有文件。

该堆栈证明反射已经进入Android 23实际`getxattr`，此次问题不是反射签名不匹配。失败发生在根目录rootfs查询可选默认ACL属性时；原实现只接受`ENODATA`，误把文件系统不支持这类可选属性当成整体平台失败。初始化又位于fixture捕获区之外，最终触发`SYSTEM PROCESS`未捕获异常报告。

### 定向修正

- 仅对`security.capability`、`system.posix_acl_access`、`system.posix_acl_default`三种可选属性，允许将`ENOTSUP`解释为该文件系统无此属性；正常返回的实际能力或ACL仍拒绝，读取权限错误和其他IO错误仍上抛。
- `security.selinux`不适用此例外：`ENOTSUP`仍失败；`ENODATA`虽表示属性缺失，随后必需标签校验仍拒绝空值或不完整值，不使用猜测标签。
- fixture参数校验、Android IO构造、环境检查、父目录与本次根创建均纳入失败处理。失败JSON记录阶段、异常类别、适用时的errno和首个错误位置；未创建本次根时只输出回执，禁止向已有失败目录补写。入口最终执行`System.exit(1)`，不再把测试错误重新抛给`app_process`未捕获处理器。
- 此次没有修改祖先属主或权限核验、目标映射、全局维护锁和原像恢复合同。
