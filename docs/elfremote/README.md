# D31 elfRemote开发记录

本目录记录D31专用客户端的开发计划及分批验收。D31沿用`net.elfradio.d31bootstrap`和原签名，与D22客户端独立开发，共用管理Web协议。

- [完整计划及并行分工](2026-09-10-D31专用elfRemote整合实施计划.md)：第十二节为当前进度与依赖安排。
- [首批统一整合验收](2026-09-11-D31并行开发整合验收.md)：构建、测试、设备验证及尚未完成项。
- [基础与完整双制品](2026-09-11-D31双制品实现记录.md)：最小蓝牙引导APK与系统完整版的边界。
- [文件新协议](2026-09-11-D31文件新协议实现记录.md)：属性、真实删除、覆盖备份及并发限制。
- [诊断比较模块](2026-09-11-D31诊断比较模块实现记录.md)：开发板、固件、目标机三方证据及离线样例。
- [Windows端口兼容](2026-09-11-D31工具ADB端口兼容实现记录.md)：保留当前端口、目标连接和急救时序。

客户端源码在`tools/D31-wireless-adb/source/`。目录名保留旧探针兼容身份，其中`basic`是首次引导与本地救援，`full`是完整elfRemote；两者不能作为不同包并存。Windows源码仍在`tools/Windows-flash/source/`。

双制品构建使用源码目录中的`tools/Build-RemoteVariants.ps1`，默认仅静态检查。实际构建使用PowerShell 7，指定`-Mode Build -CapturePath <新目录>`；需要JDK17、Android SDK及已有Gradle依赖。签名环境通过`D31_SIGNING_KEYSTORE`、`D31_SIGNING_STORE_PASSWORD`、`D31_SIGNING_KEY_ALIAS`、`D31_SIGNING_KEY_PASSWORD`注入，仓库不保存私钥。正式同包升级必须使用原证书，预览构建的`.preview`身份不能用于原地升级。

根证书和升级验证公钥是客户端运行资源，必须保留。制品标记和Android脚本固定LF换行，避免Windows签出改变标记字节或脚本行为。每次构建使用新输出目录，脚本核验源码副本、签名、版本、标记、DEX及运行依赖，生成可核对的候选清单。

研究记录中的`D31.md`、`remote.md`及原始捕获路径属于开发工作区证据索引，不随本目录公开。源码来源清单提供公开路径与原开发路径的对应关系；个人账号、设备私有日志及签名材料不在其中。

来源清单的字节数及SHA256对应冻结的原始源码字节；`Git对象`对应Git按属性规范化后的文件对象，可用`git hash-object --path=<路径> <路径>`核对。Git的换行处理可能改变签出文件的原始字节摘要，这两个字段不能混用；APK及真机测试制品摘要独立记录。

开发分支源码及候选检查不会自动变更正式下载链接。真实基础到系统完整版接替、完整取证修复、Web联调及综合实刷是否完成，以各项记录的明确结果为准。

Windows本批新增端口测试不会由历史发布构建自动运行。复跑时使用本目录已有`tools/Windows-flash/source/src/BuildConstants.g.cs`，不再追加研究目录的同名生成文件；原研究目录路径只用于追溯既有测试。历史构建依赖固件及运行工具资源，源码提交不表示已经产出新的EXE。旧真机脚本固定加载的历史版本也不能用于证明本批功能通过。

源码目录中原有`systemSupport`保持旧基线，不纳入本批同步、升级及验收。客户端`app`没有对它的编译依赖；后续固件整合仍须单独核对本地已验证的新版独立系统支持，不能直接把此开发分支当作整套最新刷机包来源。

宿主Node工具需要Node.js 18或更高版本；WebSocket检查另需在`tools`目录运行`npm install --package-lock=false`安装该目录声明的依赖。云检查工具在原参数末尾显式传入目标设备名称，两个安装检查脚本要求`-Serial`完整设备序列号；`Inspect-AdbWire.mjs`依次接收主机、端口和新捕获目录。工具不会默认选择开发板；管理员会话文件由正常网页登录取得并保留在本地。部分历史场景脚本保留其严格版本和前提检查，不等于通用于所有新版的整体验收入口。
