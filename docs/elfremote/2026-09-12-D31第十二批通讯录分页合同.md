# D31 第十二批通讯录分页合同

日期：2026-09-12。由 D22_Web_Dev 与 D31_dev 对接；本页冻结第十二批生产接线，不表示客户端或生产已验收。

## 范围与能力

- 新布尔能力为 `managed_contacts_page_v1`，只有真实上报 `true` 才开放新流程；缺失、假值及坏类型不可用。
- 新普通任务类型为 `contacts_page`。仅原厂 `LOCAL` 来源只读，不开放其他来源、写入或删除，不替换 D22 既有联系人读写。
- 新结果保存为 `task.result.contacts_page`，不得按 `contact` 前缀套用旧 `normalizeContacts`，不得写入旧 `device.contacts` 或把原厂联系人转换成 Android 号码行。

## 请求

沿用现有 `POST /api/elfremote/task` 及按原编号查询任务，不新增通讯录专用 HTTP 路由。

| 动作 | `params` | 含义 |
| --- | --- | --- |
| 建立 | `{ "action": "open", "source": "LOCAL" }` | 一次建立已完整收到的原厂回复快照，不返回联系人内容。 |
| 读取 | `{ "action": "page", "snapshot_id": "<原快照编号>", "offset": 0, "limit": 32 }` | 页长 1 至 32，偏移 0 至 4096，均为整数；按实际 `next_offset` 推进。 |
| 关闭 | `{ "action": "close", "snapshot_id": "<原快照编号>" }` | 关闭同一快照，不能代替未知的前一任务完成。 |

拒绝额外参数、错误动作、非 LOCAL 来源、字符串数字、坏类型和非法快照编号。快照编号沿用客户端小写 UUID 格式。普通任务编号、目标、到期时间及结果沿用现有任务合同。

## 结果

共同外层为 `result.contacts_page`，其内 `schema_version=1`、`action` 与请求一致、`ok` 为严格布尔、`read_only=true`、`source=nexui_messenger`、`contact_type=LOCAL`。不能仅凭普通任务成功推断内容成功。

示例时间及编号均为合成占位；真实回执仍可保留现有 `elapsed_ms/frames_received/received_chars/start_observed/max_records/max_frames/max_received_chars/wait_budget_ms/android_equivalence/service_implementation` 元数据。建立成功必须经过原 APP 操作归属及释放核验，不能直接把未经核验的 `page_snapshot` 当成功；设备端负责该已有核验链。`open` 不含 `items`。

### 分页成功

与建立快照的固定元数据完全一致，改为 `action=page`，另外包含现有 `ContactsNexui.Snapshot.page()` 字段：

```json
{
  "items": [{"mName": "合成联系人", "mNumbers": ["合成号码"]}],
  "offset": 0,
  "next_offset": 1,
  "has_more": true,
  "page_complete": false,
  "cursor_scope": "SAME_SNAPSHOT_ONLY",
  "contact_values_emitted": true
}
```

上述字段并入共同及快照字段，不是另一个结果对象。保留原厂每条对象原样；已确认显示字段为 `mName` 和 `mNumbers`，不得丢弃未知原厂字段或伪造 Android 联系人编号。每页最多 32 条；`next_offset=offset+items.length`，不得超过 `record_count`；尚有后页时必须至少推进一条。`has_more` 与实际剩余数量一致，`page_complete=!has_more`。原厂字节预算可能让实返条数小于请求页长。

### 关闭成功

共同字段加 `snapshot_id` 和 `snapshot_closed=true`；不含 `items`，不重新返回内容快照。失败或过期不能写成已显式关闭。

### 失败

共同字段的 `ok=false`，增加机器字段 `code`，例如 `CONTACTS_SNAPSHOT_GONE`、`CONTACTS_SNAPSHOT_BUSY`、`CONTACTS_SNAPSHOT_MISMATCH`、`CONTACTS_PAGE_ARGUMENTS_INVALID`。读取和关闭失败仍绑定原 `snapshot_id`；建立失败不虚构快照编号。不得带联系人 `items`，也不得把异常转换成成功空列表。普通任务按失败记录并保留该结构化结果；未知错误使用固定失败码，不向公共错误文字拼接原厂联系人值。

## 保留与页面流程

1. 页面按设备隔离快照、页游标、当前行和操作任务，不因切换设备应用其他设备回执。打开联系人功能页不自动采集，用户点击读取才建立快照；建立成功后可读取第一页。
2. 快照固定保留 120 秒，按设备原期限执行，翻页和复读不续期。网页以建立请求发送前的本机时间作保守截止，时钟倒退不可延长窗口。过期停止新内容请求并明确显示失效；重新采集必须由用户再次明确发起，不隐式 `open`。
3. 只显示当前页，上一页使用已访问偏移，下一页使用回执 `next_offset`。正常分页、回到首页不触发新的原厂全量采集。
4. 只有有效成功空页且总数为零才显示暂无联系人；错误时显示错误并保留上一页为此前读取内容，不将其当成最新成功。
5. 显式关闭释放同一快照；关闭失败保留实际错误。离开页面不承诺浏览器必然能完成关闭，设备原 TTL 仍负责清理；不启动后台自动保活。
6. 未知提交结果仅查询原任务，不能因超时或 404 自动换号建立快照。每次明确新动作只创建一次任务。快照及联系人值只保存在页面内存，服务器仍按现有任务历史保存回执；不得声称联系人内容不经过服务器或从未持久保存。

## Web 集成模块

独立模块 `research/FreePBX_VPNnode_Web/contacts-pages.js` 将导出：

- `normalizeContactsPageParams(params)`：严格规范化上述三类参数；错误时抛异常。
- `normalizeContactsPageResult(value, params)`：验证 `result.contacts_page` 的动作、身份、来源、范围、页边界及字节上限，保留受控原厂对象；返回新的规范化值，不套旧联系人列表。
- `createContactsPageController({request, now, monotonic, uuid, changed})`：按设备维护状态，负责一次提交、原号恢复、分页、期限及回执绑定；`request` 接受路径和可选 JSON 请求体。具体方法签名随实现补充，不改变上面的设备生产字段。

服务端需将 `managed_contacts_page_v1` 作为严格布尔能力保存并透传，加入新任务类型及标签；仅该能力允许新任务。结果仅在该任务下校验并保留至 `result.contacts_page`。写联系人能力不得因此开启。服务器可以校验单次回执，页面还须与建立时元数据比对，防止串快照或错误续期。

## 实现交接与检查结果

当前模块已实现以下导出：

- `normalizeContactsPageParams(params)` 与 `normalizeContactsPageResult(value, params)`：前者返回新参数对象，后者输入仅 `result.contacts_page` 内层对象。错误抛出带固定 `code` 的异常；成功返回新对象，原厂 `items` 不套旧联系人规范化。
- `validateContactsPageSnapshot(open, page)`：两参数均先经过上述结果规范化；比较全部快照固定描述字段，允许变化的只有当前分页内容字段及 `contact_values_emitted`，不匹配抛异常。
- `contactsPageSubmissionRejected(status, value)`：只识别明确入队前拒绝。400 的已知 `reason`、404 的设备不存在、409 的明确能力或快照拒绝，或 400／404／409 中明确 `not_enqueued=true`；模糊400不能当成未提交，因为现有路由的保存异常也可能返回400。
- `contactsPagesClientSource`：自包含浏览器脚本文本，定义全局 `ContactsPages`。由主任务在设备页面源码之前嵌入，不修改 Worker 的其他页面。
- `createContactsPageController({request, now, monotonic, uuid, changed})`：`request(path, body?)` 返回已解析响应；带 body 为一次 POST，否则为一次 GET。`changed(deviceId)` 通知页面重画；其余依赖均有浏览器默认实现。

控制器方法均接收当前设备对象：`state(device)`、`available(device)`、`open(device)`、`page(device, offset, limit=32)`、`next(device)`、`previous(device)`、`close(device)`、`resume(device)`、`observe(device)`。`state` 包含只属于该设备的 `snapshot/page/offsets/pageIndex/pending/busy/error/message/invalid`。`observe` 只消费设备当前 `task` 内匹配原编号的回执；不读取全任务历史、不额外启动轮询。建立成功后只自动读取第一页一次，后续翻页由用户点击。`resume` 显式查询原编号，不重新提交未知请求。

请求适配器异常可以携带 `retryAfter` 毫秒延迟、`retryAt` 绝对时间和严格布尔 `submissionRejected`。明确未入队时清除该未接受意图，允许用户再次点击发起新操作；不自动重发。未知网络或模糊服务错误保留原编号。操作完成回执需匹配原 `id/type/expires_at`，无论成功还是失败，公共任务结果均须透传 `contacts_page`。

主任务集成方案：沿设备保存 `contacts_page_snapshot` 的建立描述及固定 `expires_at=建立任务created_at+120000`；页与关闭请求需匹配原快照，页结果调用同一固定描述比对，翻页不续期。该记录不写旧 `device.contacts`。页面自身以发送前时间及单调时钟执行更保守期限；这两个期限都不能延长设备真实内存快照。

已完成 `devices-client.js` 最小接线：D31及明确支持新能力的设备显示 LOCAL 只读分页；D31尚未上报能力时只显示不可用，不回落到 D22 写入表单。D22 仍使用原联系人表单及任务。名单在设备切换后隔离，姓名与号码只作为转义文本。
