### 观察

- 完整114空闲样本中，Flinger没有录音输入线程；Policy的`Inputs dump:`至`Streams dump:`之间为空。
- Flinger包含通知客户、全局session引用表、两条输出线程和HAL子混音路由。输出线程本身也有`Input device`及`Audio source`字段，这些字段不能证明录音active；HAL路由频率非零也不能代替active证据。
- Policy的输出patch带`owner uid`，该值不提供录音客户PID和session配对。通知客户也不能冒充正在录音的客户。
- 旧ADB原件存在重复CR和额外空行。Policy硬件Gain区段有NUL；解析只规范化派生字符串，允许无关硬件区段的该现象，但输入区段的NUL或其它控制字符明确拒绝。
- 历史Zello文件为筛选后的输出轨道采样，不是完整输入转储，不用作活动输入格式证据。

### 源码核对的缺口

### 可接入口

生产类为`net.elfradio.d31bootstrap.media.AudioInputOwnership`，不依赖Android类或新增库：

```java
AudioInputOwnership.Result result = AudioInputOwnership.evaluate(
    new AudioInputOwnership.Dump(flingerText, flingerComplete, flingerBegin, flingerEnd),
    new AudioInputOwnership.Dump(policyText, policyComplete, policyBegin, policyEnd),
    appPid, audioSessionId, nowElapsedMs);
```

- `complete`只能由采集方在真实设备退出成功、完整读取、无超时且无截断时提供，宿主ADB退出0本身不够。转储正文没有万能完整性证明，本类另核对已观察到的区段顺序与尾部，不以此替代可信采集合同。
- 时间必须来自同一单调时钟。每份及两份合计观察窗口上限1500毫秒，当前年龄从最早开始计算，上限4000毫秒。超限、未来时间、倒序、未完成均返回未知。
- 两份转储不是原子快照。即便都在时间预算内，也不能排除两次读取之间或读取之后出现输入客户。`atomicReservation=false`固定；此结果不能独立作为生产媒体启动或持续录音准入。
- 每份文本最多262144个UTF-16字符、8192行、每行4096字符；超限拒绝，不丢尾。负责采集者必须在读流时另设字节上限，避免先无界收集再调用解析器。
- `ownPid`与`ownSession`必须为正且来自本次真实APP/AudioRecord。当前只验证其参数形状，不证明身份；不能从任务入参自报值获得豁免。
- `Result`只带脱敏`state/reason/activeInputs/scope/selfExemptionAllowed/atomicReservation`，不返回转储原行、客户标识或内存指针。
- 当前只可能返回`UNKNOWN`或`NO_ACTIVE_INPUT`；后者仅表示这对已接受转储没有输入条目，范围为`D31_114_DUMP_INPUTS_ONLY_NOT_ATOMIC`，不代表蜂窝、SIP、焦点或播放空闲。
- `SELF_ONLY/OTHER_ACTIVE`为待真实活动格式确认的状态，当前没有代码产生它们；`selfExemptionAllowed=false`固定。出现输入线程、非空Policy输入区段或不认识的结构时拒绝，不能将缺少支持说成已辨认其它录音。

### 活动格式的观察

第06、07组Flinger实际出现`Input thread ... type 3 (RECORD)`，`Standby: no`、普通MIC、16000赫兹、mono、PCM16，且明确写出`1 Tracks of which 1 are active`。列头为：

```text
Active Client Fmt Chn mask Session S Server fCount SRate
```

两次轨道的`Active=yes`，`Client`等于本次回执的APP PID，`Session`等于本次AudioRecord session；全局session引用表也具有该配对。决定active的是输入轨道的明确列和计数，不是全局引用表。`S`内部状态值不解释为公开录音状态，通知客户不作为录音客户。

两组Policy均有与Flinger相同的`- Input <handle> dump:`、相同采样率、格式、声道和输入设备，以及正的`Ref Count/Open Ref Count`。Policy的`ID`是另一个字段，不能替代I/O handle，更不能当作PID、UID或session。Policy本身没有本次客户PID/session列；归属证据来自Flinger，Policy只作输入存在和配置的旁证。

下表以回执`capture_started_elapsed_ms`为零点，结束值包含10毫秒精度保守上界。该零点在实际启动调用之前，结束回执又在释放之后，因此这是诊断外层时间范围，不是原子active区间。
