# D31普通受控文件修复事务实现记录

## 2026-09-11：首批离线核心

本记录对应整合实施计划11.5、11.8及第二批并行任务。已实现可注入平台、持久日志和真实临时文件测试。完成范围是普通文件内容替换的离线事务核心，尚未完成真机修复、远程调用或业务生效验收。

已有文件差异只能作为证据输入；证据摘要不是根因结论，也不是自动改写授权。当前没有生产执行器、网络能力标志、共享入口或自动恢复调度，不执行真实`/system`写入、分区操作、账号变更、服务重载或任意命令。

### 方案与授权合同

- 方案明确登记任务号、方案号、修订、设备类别、精确目标构建、证据摘要、每项逻辑路径、原像及目标SHA-256和字节数、目标载荷标识、变更顺序依赖及只读文件依赖。
- 仅支持现有普通文件替换；不创建或删除目标，不接受绝对路径、路径穿越、命令字符或未定义字段。最多16个目标、32个只读依赖，每文件最多64MiB。
- 变更按方案列表顺序执行，`after`只能引用此前登记的不同变更；拒绝重复目标、自依赖、环及目标与只读依赖重叠。每次前向推进都重新核对审批、构建、允许路径和只读依赖。
- 可信`allowedPaths()`由平台提供，不能直接采用客户端方案生成允许清单。逻辑路径不得映射到分区、账号、凭据、身份或校准数据。路径语法校验本身不能证明映射对象适合修复。
- `approved(planSha256)`必须绑定完整方案摘要。摘要使用固定字段顺序编码，包含任务号和全部参数，不受JSON键顺序影响；同任务号同摘要返回原记录，参数不同拒绝且保留原方案。
- 前检检查原像类型、摘要、长度和空间。空间预算为8MiB日志余量加全部原像长度三倍、目标长度两倍；平台需报告相关存储卷的保守可用空间，实际磁盘异常仍按失败分支处理。

### 调用与持久日志

`new RepairTransactions(journalRoot, platform)`只创建日志设施，不执行修复。`submit(plan, now)`仅登记；`step(taskId, now)`由调用方显式推进；`query(taskId)`只读已提交记录，不依赖网络、执行平台或维护锁。没有定时器、后台线程或开机自动推进逻辑。

任务目录保存不可变`plan.json`、连续编号的完整状态记录及`backup/`、`stage/`副本。状态记录包含序号、时间、方案摘要、前一原始记录摘要、阶段、失败原因及实际文件观察。异常只记录类别和固定原因，不持久化适配器异常消息，避免把凭据写入日志。

每份日志先写唯一临时文件并执行`FileDescriptor.sync()`，再改名为新记录。原记录和残留临时件不覆盖、不清理。加载检查序号和摘要链；损坏或缺号拒绝执行。日志链用于发现记录不一致，不能代替访问控制，也不保证识别整体尾部被删除或全部记录被恶意重写。

写入持有独立`transaction.lock`，不锁住备份内容文件，避免Windows持锁数据文件无法另开读句柄的问题。查询读取枚举时已提交的不可变快照，执行持锁期间也可查询，返回对象修改不影响日志。文件系统完全不可读时查询会报错，不能把存储失效等同于网络失联保证。

单任务最多256条记录，最多128个任务目录；需要外部显式归档后才可继续增长。未结束任务以及`NEEDS_ATTENTION`阻止同一日志根目录接收新任务；核心没有自动清理或解除人工处理状态的接口。

### 阶段与中断判定

| 阶段 | 行为与恢复规则 |
| --- | --- |
| `PENDING` | 前置检查通过后进入备份；失败为`REJECTED`，没有目标写入 |
| `BACKUP` | 保存并核验全部原像；已有副本必须正确，残缺副本保留并拒绝；缺失副本仅在重新确认现场后允许复制 |
| `STAGE` | 暂存并核验全部目标内容；不覆盖已有暂存件 |
| `SWITCH_READY` | 再核对现场、依赖、全部备份及当前暂存件，然后先记录切换意图 |
| `SWITCH_INTENT` | 同次调用只切换一次并回读；重开后目标已是新内容则仅确认，仍为原像则转回滚而不重发，其他内容保留 |
| `VERIFY` | 检查全部目标、调用可重复只读生效核验，再次检查内容；两者均通过才完成 |
| `ROLLBACK_READY` | 逆序处理已尝试目标；仅当现场仍等于本方案目标且备份原像正确时允许恢复，恢复前记录意图 |
| `ROLLBACK_INTENT` | 重开仅核对实际原像及目标环境；未确认恢复则要求人工处理，不重复恢复写入 |
| `SUCCEEDED` | 方案内容及平台限定的只读生效检查通过 |
| `ROLLED_BACK` | 所有目标回读为原像且没有未确认恢复项 |
| `NEEDS_ATTENTION` | 外部内容、读失败、备份缺失、环境变化或回滚不确定；保留证据且不自动继续 |

每次`step`最多一次目标切换或恢复。没有跨文件原子提交保证；依赖顺序、先存意图、逆序恢复和每步实际哈希共同限定部分完成状态。终态再次调用不写目标。失败后的回滚须由调用方继续显式推进，断线本身不会启动任何自动行为。

切换和回滚发生日志故障时抛错，已提交意图保留供下一次显式调用判定；意图未成功持久化时不开始目标改写。回滚不覆盖外部内容，不改未尝试目标，最后只读检查全部目标。回滚授权包含在获批的完整方案内，不重新要求前向依赖成立，但仍要求类别、构建及目标允许路径成立；这允许在依赖失效后恢复原像。

### 父任务整合点及验收边界

1. 将`RepairPlatform.acquire()`桥接现有维护锁，与账号配置、自更新、Windows维护共用冲突控制。占用返回空租约，真实锁异常必须失败关闭；现有`RemoteFileLocks`对Android 6的`EAGAIN/EACCES`处理仍由父任务复用，不复制到新包或绕过锁。日志锁只负责本根目录串行，不能替代全局维护锁。
2. 日志根目录必须是可信私有目录，且固定绑定同一目标实例，不允许跨设备共享或指向可被其他写入者修改的目录。生产适配器还须保护允许路径解析、链接和并发写入；测试适配器只在隔离临时目录内执行，没有证明对不合作外部写入者的原子比较替换。
3. 目标映射、离线载荷来源、准确构建查询、审批摘要和只读生效验证由父任务提供。平台`replace`必须在稳定文件与锁保护下先检查原像再原子切换，保留备份原件；复制后删除不满足合同。`verify`不能仅以命令退出码或差异报告宣称业务正常。
4. 当前仅有文件内容、长度与类型合同，不迁移属主、权限、SELinux标签或扩展属性，不验证系统更新副本优先级、进程载荷切换、重启生效或业务连续性。需要这些动作的方案不属于首批普通文件验收，应先扩展已审查合同和独立测试。
5. 日志文件同步与改名尚未验证真实断电后的父目录持久性。无真实适配器、无真机执行、无重启恢复、无双机对比闭环；不能据离线22项通过宣称计划11.5或11.8整体完成。

本批未修改共享入口、版本、Manifest、Gradle或Web，未新增网络能力标志，未开启自动修复，也未执行Git提交。后续Android统一编译和测试由父任务安排。
