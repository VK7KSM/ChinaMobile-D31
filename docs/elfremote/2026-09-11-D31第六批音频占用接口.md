## 接线合同

Dirac已经冻结的工厂接口为 `AudioGuard create(Context) throws Exception`，接线方法如下：

```java
public AudioGuard create(Context context) throws Exception {
    return new AndroidAudioOccupancy(context).start();
}
```

`AndroidAudioOccupancy` 实现现有 `AudioGuard` 与 `AutoCloseable`：

- `AndroidAudioOccupancy(Context)`：不执行文件、Binder或Provider操作，不创建实际工作线程。
- `start()`：返回自身，首次调用只提交后台任务；重复调用不新增任务或线程，已关闭后拒绝重启。
- `snapshot() throws Exception`：只读缓存并返回新的 `JSONObject`，没有Binder、进程或文件操作。字段 `cellular/sip/other/state` 为 `IDLE/BUSY/UNKNOWN`；另有 `idle/reason`、`sample_started_elapsed_ms/sample_finished_elapsed_ms/age_ms/max_age_ms/refresh_delay_ms` 与来源范围。
- `requireIdle() throws IOException`：只检查缓存，所有来源均明确空闲才通过；占用或未知抛异常。不会因SIP注册成功或模式NORMAL单独放行。
- `close()`：服务dispose时必须调用；立即令缓存不可用于放行，取消调度，不等待Binder无限返回。已经阻塞在系统Binder内的唯一守护线程可能尚未退出，不宣称中断Java线程能终止远端调用。

主任务负责只在完整制品的实际服务生命周期创建工厂产物，保留对象并在服务dispose时关闭。本批不改 `RemoteApplication/AppMediaService/AudioGuard`。

刷新采用单线程固定延迟，每次完成后至少等待2000毫秒；媒体100毫秒检查循环只查内存。快照从采样开始计龄，超过4000毫秒拒绝；单次采样超过1500毫秒或时钟逆行也拒绝。启动前、首个快照前、读取异常、API缺失、过期和关闭均明确未知。Binder长时间阻塞不会触发替代线程或累积排队采样。没有dumpsys轮询、shell进程、注册音频焦点或修改路由。

该合同是有时效的观测，不是原子音频预留；状态变化到下次有效采样之间存在检测延迟。调用者不得将其宣称为绝不与新通话并发。

## 录音所有者限制

全局输入布尔值不提供所有者。本批不因调用者说“自己正在录音”就忽略其他输入；若检测到自身录音同样会否决，这可能让持续媒体会话在下一次刷新后停止。因此本版本不能宣称已经解除了所有实际录音阻断，也不能把自身会话正在运行当作豁免其他应用的充分证据。

## 2026-09-11 23:27 追加：首次采样有界观察接口冻结
