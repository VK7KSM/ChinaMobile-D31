## 公共接口与接线

生产构造使用公开类，不要求根包访问包私有实现，也不依赖Context、注册结果、MQTT或HTTP：

```java
import net.elfradio.d31bootstrap.faults.*;
import net.elfradio.d31bootstrap.diagnostics.collection.AndroidCollectionAccess;

FaultMonitor monitor = new FaultMonitor(
    new File(AndroidFaultSources.ARCHIVE_ROOT),
    new AndroidFaultSources(),
    AndroidCollectionAccess.systemClock(),
    FaultPolicy.defaults());
```

`FaultMonitor`构造可抛`IOException`，会准备并核验私有归档根。生产根固定为`/data/local/d31-remote/faults`，其父目录必须已由完整客户端建立；要求根目录为root属主、root组、0700，原始文件0600。构造失败由核心记录为本地采集不可用，不得影响已有远程管理。

| 公开调用 | 实际行为 |
| --- | --- |
| `FaultMonitor.Submission tick()` | 与`collect()`相同，立即返回提交结果，无同步采集 |
| `FaultMonitor.Submission collect()` | 返回`ACCEPTED`、`BUSY`、`THROTTLED`或`CLOSED`；单工作线程、不积压队列 |
| `boolean isBusy()` | 当前实例工作是否仍在执行 |
| `String lastOutcome()` | 最近执行结果，初始`NOT_RUN`，随后为`FINISHED`、`THROTTLED`、`CAPACITY_LIMIT`或`FAILED` |
| `String lastFailure()` | `NONE`或固定错误码，不包含异常原文 |
| `JSONObject query(String eventId)` | 读取原事件及尝试索引，可能抛异常，不启动采集 |
| `JSONObject index(int limit)` | 按事件摘要排序读取1至64项；含总数及`hasMore`，当前没有分页游标 |
| `void close()` | 关闭入口并中断工作，不删除原件 |
| `static JSONObject readQuery(File root, String eventId)` | 无需监控实例读取已有归档；根不存在即失败，不创建目录 |
| `static JSONObject readIndex(File root, int limit)` | 无需监控实例读取已有索引 |

公开可注入接口`FaultSources`提供`discover(FaultPolicy)`、`capture(Candidate, File, FaultPolicy)`、`context()`、`bootKey()`、`checkPrivateRoot(File)`和`replace(File, File)`。其中`Candidate`、`Scan`、`Capture`均为公开嵌套类；时钟使用现有公开`CollectionAccess.Clock`。生产适配器固定来源，不从远程请求接收路径映射或命令。

主核心应长期持有一个实例，在本地循环低频调用`tick()`，或收到明确本地事件时调用`collect()`；两者均遵守最短间隔。调用位置必须独立于云注册、云请求或上报成功分支。当前本线没有修改`RemoteWorkLoop`等公共入口，不能称自动取证已经启用。

监控器仅持自己的`collector.lock`保护故障归档，使用非阻塞跨进程文件锁；不取得或新造设备全局维护锁。查询不等待采集锁。它不写生产来源或修改系统设置，核心不应为了等待采集而长时间持有维护锁。

依赖仅为项目已有diagnostics、`org.json`、Android系统API及既有`/system/bin/busybox`目录枚举器。没有新增第三方库、权限或网络能力标志。Android来源的目录枚举复用现有有超时和输出预算的BusyBox `find`实现；不经任意shell输入，不启动常驻logcat。

## 已实现来源与范围

| 来源 | 编译期路径与筛选 | 能证明的范围 |
| --- | --- | --- |
| ANR | `/data/anr`中的`traces*.txt`及`anr_*`受控名称 | 实际存在且可读的文件；来源时间取文件修改时间，不能冒充ANR发生时间 |
| 原生崩溃 | `/data/tombstones/tombstone_XX`及相应受控编号、可选`.pb`后缀 | 冻结原始字节，不把二进制解释成已解析线程堆栈 |
| DropBox | `/data/system/dropbox`下应用或系统崩溃、ANR、`SYSTEM_TOMBSTONE`、`SYSTEM_SERVER_WATCHDOG`标签 | 保留`.txt`、`.dat`、`.gz`原始字节，不解压造成无界输出；`.lost`明确为`DROPBOX_ENTRY_LOST` |
| 已有启动日志 | `/data/local/d31-remote/supervisor-launch-*.log` | 路径依据`RemoteManualBootstrap.launchSupervisor()`的真实日志创建逻辑；日志存在不等于启动失败 |
| 窗口状态 | 固定`/proc/meminfo`、`/proc/loadavg` | 内存与负载文本采样，不包含账号目录、进程命令行或应用个人内容 |

每个来源目录最多枚举64项，共最多256个候选；总发现阶段默认5秒，单文件身份采样最多4096字节。权限拒绝、来源不存在、枚举截断和不稳定分别保留在覆盖索引，不以空列表声称没有故障。生产路径、权限、DropBox实际命名及API23调用仍待总负责人只读验证。

去重身份绑定类别、受控路径、文件元数据及前4096字节摘要；没有内容的假事件模板。相同大小和同秒时间的前缀变化可被识别，但只发生在未读取后缀、且元数据完全相同的变化可能漏检；文件在两次轮询间生成并被清理也可能漏检。这是明确有界的来源观测，不是无损系统事件监听。

`eventMeaning=SOURCE_FILE_OBSERVATION_NOT_CONFIRMED_NEW_INCIDENT`，累计次数为`POLL_SIGHTINGS_NOT_CRASH_COUNT`，上限一百万。不能把重复看见旧文件当作反复崩溃，不能把既有启动日志当作新故障。任意进程退出、反复重启及启动超时的实时判定本批尚未实现。

## 原件、恢复与预算

每个事件目录名为摘要；`event.json`、`pre-*.json`、`post.json`、`attempt-N`内原件和`report.json`排他创建。`state.json`、`scan.json`及`schedule.json`是可原子替换的派生查询或调度状态，与不可变原件分开。文件写入执行同步；本批没有断电持久性验收，不声明等价于掉电事务。

事件最多32个，总归档默认64MiB，至少保留32MiB可用空间；新增事件预留原件、三次尝试及上下文预算。每轮最多推进或新增8个事件，单份原件最多256KiB。大文件保留前缀且原诊断标记`TRUNCATED`，不是完整日志。容量满返回`CAPACITY_LIMIT`，保留旧证据而停止新增，不自动清理、不套用普通媒体七天删除规则。

默认tick间隔60秒；同开机周期的间隔同时持久化，独立命令重复启动不能绕过限频。采集失败最多三次，重试间隔为60秒、120秒；来源身份变化或已明确截断不无限重试。故障前后窗口不通过线程睡眠等待，只在后续tick推进。时间和字节预算是协作式检查，不能保证内核单次文件调用卡住时硬实时返回；异步工作不会形成多线程或无限任务积压。

恢复首先读取事件和已有尝试：已有完整报告直接复用，不重新采集；有尝试目录但无报告标为`INTERRUPTED`，原字节保留且占用一次重试名额，后续使用新编号。坏报告在查询中明确为`INDEX_CORRUPT`，本轮索引保留`eventIndexErrors`，不能阻断其他正常事件的采集。主进程失联不清除任务，之后仍可查询同一事件。

## 故障前后窗口的真实含义

后台实例仅在每次执行结束取得一次内存、负载采样，进程内最多保留4份、最长5分钟；事件发现时冻结已有采样。没有事前采样为`MISSING`，采样不可用为`PARTIAL`，不会用当前数据倒填。进程退出后尚未冻结的内存环不恢复；已有事件的冻结原件仍保留。

后窗口最早在发现30秒后、最迟5分钟内由后续tick取得一次采样；超过窗口、设备重启、单调时钟倒退分别为`MISSING_DEADLINE`、`MISSING_REBOOT`、`MISSING_CLOCK_ROLLBACK`。独立`FaultCommand collect`进程没有长期事前环，首次通常缺事前采样；它不等待后窗口，需以后一次采集推进，不能声称独立单命令已完成前后连续日志。

窗口锚点是本地发现时间，来源时间为文件修改时间。`beforeFaultCoverage=NOT_ESTABLISHED`及`preFaultLogcat=UNAVAILABLE`始终明确：已取得的采样不证明覆盖实际故障前时间段。未收集连续logcat、应用线程转储、网络业务快照或完整CPU历史。最终`COMPLETE`仅表示`SOURCE_BYTES_AND_SAMPLED_CONTEXT`范围内原件及有效前后采样完成，不代表根因成立、系统一致或业务已经修复。

## 独立命令与只读设备验收建议

公开入口为`net.elfradio.d31bootstrap.faults.FaultCommand.main(String[])`，只接受以下参数组合：

```text
collect
query <64位事件摘要>
index <1至64>
```

兼容只读入口`FaultQueryCommand`还保留`query <摘要>`及`index <数量>`。两者生产入口检查root、Android23及已确认D31设备字段。所有命令都不读云凭据、不申请网络连接、不启动故障源进程；`collect`只写自己的故障归档，不修改被采文件。命令最多等待本次后台工作90秒，超时返回明确失败，后续查询中断原件。

由总负责人填入已核验活动APK摘要后，通过现有`root_exec`发送，`params.cwd`为`/`、`params.timeout`建议120：


## 2026-09-11：主任务自动调度接线只读复核

主任务随后新增公共`RemoteFaultRuntime`并接入`RemoteDaemon`，替代前文“自动tick尚未接线”的当时状态。本线只读核对了其构造、60秒首次延迟及周期、`bootComplete`检查、维护预留检查和finally关闭，确认调用均与上述公开API兼容，没有修改公共文件。普通断网异常在主循环退避，不阻塞独立scheduler；维护预留期间跳过当轮，释放后下一轮重新检查。新出现预留不会追溯取消已提交的只读采集，该代码没有承诺全程持有维护锁。

本次发现并回告一个实际生命周期缺口：尚无`device_id`时，`RemoteDaemon.tick()`直接执行enroll；其非429的4xx异常在主循环触发退出，finally随即关闭故障scheduler。如果拒绝发生在首次60秒前，自动取证没有执行机会。已注册后的接口拒绝由`RemoteWorkLoop`捕获，不能把这两个路径混为一谈。建议由主任务在停止云注册重试时保留本地故障调度；独立`FaultCommand`始终不依赖enroll。此条是源码控制流复核，不是设备上已复现或已修正的声明。

新增公共接线尚待主任务组合编译、API23及实际设备验证。本包源码仍保持最终36项离线测试对应状态，未因本次评审改写。
