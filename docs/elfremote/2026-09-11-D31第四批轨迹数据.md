
注入接口：`Clock.wallTimeMillis()`和`Clock.elapsedRealtimeNanos()`；`Access.location(Limits,Clock)`及`Access.battery()`。公开不可变输入为`Fix`、`LocationReading`和`BatteryReading`，构造参数见生产类。所有字段来自调用者或真实Android读取，不自动产生设备标识或凭据。

合并入口最终名称为`mergeReport`，不是早期草拟的`mergeInto`。方法返回报告副本，保留调用者的编号、报告时间、网络和其它业务字段，不修改原对象。已有任一遥测字段时拒绝再次合并，防止重新采样污染离线原件。`reportFields()`仅用于检查采集结果；正式报告必须通过`mergeReport()`的新鲜度门。

主任务当前接线形状：

```java
TelemetryCollector collector = new TelemetryCollector(
        new AndroidTelemetryAccess(context), AndroidTelemetryAccess.clock());
// 主任务工作线程执行；仅报告生成且bootComplete后触发。
TelemetryCollector.Sample sample = collector.collect(new TelemetryCollector.Limits(0, 300000));
// 主任务已有新报告含真实report_id和reported_at；只合并一次。
JSONObject frozenReport = sample.mergeReport(newReport, System.currentTimeMillis(), 1000);
// 交回现有pending-report.json持久化和确认流程。
```

上例1000毫秒是快照新鲜度门示例，不是固定等待或新调度节拍。主任务采用单工作线程、最多等待250毫秒、保留尚未返回的Future、不再启动第二个被阻塞线程；下一报告使用晚到结果时仍必须过新鲜度门。取不到合格快照时由主入口明确填缺失，不得复用不受时间门约束的旧字段。

## 采集与缺失语义

- 首次接线固定`Limits(0,300000)`，只读最近5分钟GPS/网络定位缓存及电池粘性广播。不会开启定位、主动请求新位置或扫描Wi-Fi。
- `locationWindowMs`允许0至10000毫秒，非零时才启用一次性监听。该路径已实现但不属于本批接线和设备验收；后续主动采样子批另验。`maxLocationAgeMs`允许1至900000毫秒。
- API23读取`LocationManager`真实来源、经纬度、精度、采样墙钟及单调时间。拒绝模拟位置、未知来源、无效坐标、非正或非有限精度、过期/未来时间和单调时间不符。未报告精度时保留`acc_m:null`，不会补造精度常量。
- 真实有效缓存标记`recent_cache`，实际新采样标记`sampled`；权限不足、服务不可用、定位关闭、超时、无缓存分别保留原因。监听清理结果在本地证据`listener_released`中保留；清理失败的访问实例不再注册新监听。
- 读取`ACTION_BATTERY_CHANGED`时使用`hasExtra`区分缺项。只有明确存在电池且`level/scale`有效才产生百分比；电池不存在或存在状态未知都不产生伪造100%。
- `charging`只由有效`plugged`位判断，满电插着电源仍为真。缺少插电证据时为JSON空值；不根据进程正在运行推断外接供电。原始`level/scale/plugged/status`与`ac/usb/wireless/external/battery/unknown`分类留在本地证据，不发明新的Web字段。
- 合并快照年龄允许0至60000毫秒；超期、墙钟倒退或采集期间检测到明显时钟跳变时，所有遥测字段变为缺失，原因`snapshot_stale`。快照仍新鲜但位置本身过期时，仅清空定位，不清空真实新鲜电量。
- 中断向调用者传播并恢复中断标记。普通读取异常只保留稳定原因分类，不把异常消息、个人数据或凭据写入报告。

合成字段示例，仅说明JSON合同，不表示真实设备或真实位置：

```json
{"gps":{"lat":0,"lng":0,"acc_m":25.5,"provider":"gps","at":"2026-09-11T00:00:00.000Z"},"location_reason":"recent_cache","battery":50,"charging":true,"battery_present":true}
```

```json
{"gps":null,"location_reason":"no_cached_location","battery":null,"charging":true,"battery_present":false}
```

`Sample.toJson()`提供版本1的本地快照合同，包括`started_at_ms/captured_at_ms/elapsed_ms/clock_stable/max_location_age_ms/fields/evidence`。其中电池时间是本次读取粘性广播的观察时间，不冒充硬件内部测量时刻。快照可供调用者记录证据，但本模块不建新队列、不发网络请求、不持久化媒体或另设重试任务。离线正式报告仍由既有`pending-report.json`保存首次合并后的完整原件，重传不得重采样、改时间或改编号。

## 媒体关联边界

`photo()`仅建立真实报告编号、拍摄毫秒时间、字节数和摘要元字段。照片4至262144字节，摘要为64位小写十六进制；调用者仍须核对实际JPEG、字节摘要和服务器结果。编号使用报告与照片共同接受的`[A-Za-z0-9_-]{1,96}`子集，与当前UUID报告编号兼容。

`automaticPhotoEligibility()`仅核对同号成功回执及自动照片网络规则；`ELIGIBLE`不是已上传或服务器完整准入证明，仍需服务器确认24小时时限、真实历史、JPEG和有效许可。不会替调用者产生低电量事件或手动许可。

`recording()`仅返回本地音视频索引，保留真实起止时间和明确传入的报告/任务编号；未传报告编号则`UNLINKED`，传入时标记`EXPLICIT_REPORT_ID`，均为`transport_state=NOT_INTEGRATED`。不能用最近报告的位置推测媒体位置。照片/媒体交叉关联和真正上传由C线及主任务接入。
