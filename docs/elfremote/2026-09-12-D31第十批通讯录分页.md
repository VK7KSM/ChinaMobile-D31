## 原厂证据与边界

再次读取冻结客户端`research/d31/analysis/2026-09-08-sip-network-gate/build-20260908-134918/smali/com/starnet/contactclient/ContactClient.smali`及第九批专项。`handlerLocalMsg`从`sendState`与`all_contacts`消费分片，`getMsgBundle`只包含`contact_type/action_type`，`sendMsgToServer`使用独立`replyTo`发送Messenger消息。既有`ContactsLocalReadAndroid`继续只发一次`LOCAL/all_contacts`，没有新增原厂消息、观察器、手动刷新或同步命令。

已知事实：原厂协议提供分片完整回复，没有已验证的原厂分页游标、数据库世代或跨分片一致性标记。第九批和128真机已有LOCAL合法结束帧证据，但服务端DEX加密、启动内部副作用仍未完全解释。

本批据此采用一次完整回复的内存快照分页。跨页内容冻结，不因为每页重新读取而混合两次回复；`page_consistency=IMMUTABLE_RECEIVED_REPLY`仅声明此事实。`snapshot_consistency=NOT_PROVIDED_BY_VENDOR`保持，不能称为原厂数据库原子快照。`all_sources_complete=false`保持。

本入口只接受LOCAL，不接受BLUETOOTH、EAB、CONFER、FAVORITE或Android号码行；不合并来源、不写联系人、不读取照片或组织树。条目保留原厂JSON字段，不伪造统一联系人ID、主键或号码类型。来源标记放在每份快照及每页中，所有`items`均属于该页明确标注的LOCAL来源。

## 数据及生命周期

1. 建立快照前取得既有根维护预留；APP握手后经原有PID、UID、APK摘要与进程代次核对并持久登记ARMED，才执行一次原厂读取。
2. 继续使用4096条、128帧、单帧131072字符、总1048576字符、单条8192字符上限，以及原有8秒读取、10秒工作、11秒专用进程硬截止。超限、超时或缺结束帧不能发布部分联系人内容。
3. 收到完整END后，仍须确认回信线程关闭和原厂解绑。`ContactsLocalRead.Capture`仅在这次调用栈内暂存候选；异常或失败通过`close()`丢弃，只有清理成功的快照才转移给`ContactsPageStore`。
4. 一个APP专用进程最多保留一份快照，固定120秒，不因翻页续期。使用`SystemClock.elapsedRealtime()`；时间倒退按失效处理。到期回调、后续请求和服务创建均检查过期。进程死亡、应用升级和整机重启不承诺保留快照。
5. 后续页只读这份不可变内存快照，不再启动或绑定原厂服务。根侧仍取得现有`RemoteContactsAccess.acquire(hash)`维护租约，不另设全局锁；此时原厂资源已释放，缓存本身不占用长时间维护预留。
6. 每页1至32条，并继续执行12000字符内容预算。实际条数可小于请求值，必须依据`next_offset`推进。内容页走单独的65536字节APP回执上限，旧元数据仍保持8192字节上限，不把完整列表塞进一笔Binder事务。
7. 快照编号、APK摘要、boot必须匹配。过期或进程丢失返回`CONTACTS_SNAPSHOT_GONE`；错配返回`CONTACTS_SNAPSHOT_MISMATCH`；已有快照时新建明确`CONTACTS_SNAPSHOT_BUSY`，不能覆盖旧缓存。无隐式重采集，无跨重启续页。
8. 页取消、生成异常及生成中到期不能返回部分数据；匹配的缓存关闭或失效。显式关闭只作用于匹配的快照。原厂解绑未知仍保留既有生命周期占位及根预留，由既有恢复路径处理，不能因内容缓存结束而假称原厂资源已释放。
9. `lastLocalResult`和根操作记录仅保存建立快照的脱敏元数据及快照描述，不保存`items`。联系人值只存在APP缓存、显式内容页、根页消费者和验收私有原件中；本实现不承诺JVM堆的密码学擦除。

快照只表示已经收集的回复。用户在分页期间增删联系人不会改变既有页；需要关闭旧快照并使用新操作编号显式采集。重复原操作编号沿用持久操作回执，不隐式创建第二份快照；旧描述不能保证当前缓存仍在，实际读取明确检查失效。

## 公共接线合同

本线没有修改下列公共类，已向主线交接：

| 公共位置 | 需要的最小接线 |
| --- | --- |
| `RemoteAppOperation`操作准入和持久记录 | 新类型`read-local-pages`，参数严格为空对象`{}`。不得复用`read-local-metadata`同号结果冒充内容采集。 |
| `RemoteAppOperation`参数与回执校验 | 新类型沿用通讯录APP身份及清理合同，`kind=NEXUI_APP_LOCAL_METADATA`，同时严格要求`operation=read_local_pages`。旧metadata合同不变。 |
| `RemoteAppOperation`显式恢复 | 新类型调用现有`recoverLocalMetadata()`，只查询或取消原请求；不发送新采集。缓存已包含`operation=read_local_pages`及原请求ID、APK摘要。 |
| `RemoteAppOperationFiles.application()` | 新类型选择`net.elfradio.d31bootstrap:contacts`，继续实际PID、UID、启动时间、安装/映射APK验证。 |
| `RemoteContactsAccess` | 不需要修改。后续页与关闭使用原`acquire(hash)`；建立快照直接调用通用`RemoteAppOperation.begin()`。 |
| 公共能力、任务分发与Web | 本轮不自动开放通讯录全源列表或写入。网页接线要消费明确的LOCAL来源、快照编号、分页边界与失效状态，不能把旧128计数当列表。 |

已实现的调用接口：

```java
RemoteAppOperation.begin(context, "read-local-pages", operationId, sha256, new JSONObject());
bridge.openLocalPages(sha256, control, operation::arm);
bridge.readLocalPage(sha256, snapshotId, offset, limit, control);
bridge.closeLocalPages(sha256, snapshotId, control);
```

建立快照仍由`ContactsAppService.finish()`先设置`operation=read_local_pages`，再缓存脱敏结果；`INSPECT_LOCAL`恢复返回这份缓存。后续内容页回执单独为`kind=NEXUI_APP_LOCAL_PAGE`，`vendorRequestSent=false`，不得交给建立快照的`operation.finish()`，避免把个人值写入根维护记录。

新增CLI为`net.elfradio.d31bootstrap.management.ContactsPageCommand`：

```text
open <活动APK的SHA256> <新操作编号>
page <活动APK的SHA256> <snapshot_id> <offset> <limit>
close <活动APK的SHA256> <snapshot_id>
```

`open`只输出脱敏元数据，成功后从`page_snapshot`取得编号；`page`明确输出联系人内容；`close`不输出内容。不支持额外来源、写入、刷新或删除参数。未接通公共操作类型时`open`以`APP_OPERATION_KIND_INVALID`拒绝，不降级为绕过维护门的执行。

## 主线设备验收

目标仍为D31/API23，使用5042服务器及本次实际完整网络序列号。主线先统一构建并覆盖安装包含公共接线的新完整候选，确认实际活动APK与安装APK摘要一致，再在全新私有目录运行：

```text
node research/d31_adb_bootstrap/tools/Verify-RemoteContactsPage.mjs <D31完整序列号> <新版本号> <活动APK的64位小写SHA256> <全新私有捕获目录> [每页条数]
```

工具默认每页一条，最多128页。真实列表较大时显式使用较大页长，最大32；超过本次宿主页数或120秒缓存期限则失败并关闭，不假称取完整列表。空列表可以验证合法END及关闭，但摘要`crossPageExercised=false`，不能宣称跨页已测。

验证流程为：构建和boot/活动及安装APK核对；一次建立快照；逐页核对来源、编号、总数、字段、游标和最终结束；复读首页确认同一内容；显式关闭；再次使用关闭的游标必须返回`CONTACTS_SNAPSHOT_GONE`；最后核对APP按需服务退出、原厂服务状态和设备身份。

所有ADB命令使用唯一末尾远端退出标记，保存完整原始标准输出、标准错误、命令、时间及退出码；失败也保留原件，不自动重复采集、安装、停止服务、重启或恢复。工具控制台及`result.json`仅含来源、条数、页数、通过状态和固定错误码，不含姓名、号码、lookup、快照编号、设备身份或APK摘要。原始页只进入命名为私有的文件，整个捕获目录不得同步到公开源码或发布制品。

若建立快照阶段失联或清理未知，工具不会伪造释放；按本次私有`scope-private.json`中的操作编号，通过既有`RemoteAppOperation query/recover`处理。若只是在内容页失联，则使用原快照编号关闭；无法通信时快照到期失效，不重新触发原厂查询。

本线未执行任何上述真机动作。主线仍需验APP进程跨请求存活、实际Binder字节上限、正常及故障后的专用服务退出、真实内容与设备本地显示的私有对照。其他来源、Web列表端到端、跨进程/跨boot持久快照、联系人写入均未实现或未验收。
