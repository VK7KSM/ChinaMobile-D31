# D31第十二批网络确认冻结合同

记录：2026-09-12，D22_Web_Dev。依据第十一批网络生产确认合同，本批开始实现Web接线；Android由D31_dev实现。下述为本批冻结线协议，不代表已完成联合验收。

## 范围和开放门

仅支持D31的Wi-Fi布尔开关。保留原`system_config`任务及`POST /api/elfremote/task-progress`，不创建第二任务或队列。D22原语义保持。报告新增`managed_network_confirmation_v1`布尔能力与`network_write`布尔开关；两者均为true且系统配置已支持时才能新下发，当前设备须保持`network_write=false`直到联合验收。确认及终态不因能力随后撤回而丢失原任务核查路径。

## 管理员下发与设备领取

`POST /api/elfremote/task`示例（标识均为合成示例）：

```json
{"device_id":"demo-device","id":"network-demo","type":"system_config","params":{"group":"wifi","action":"set","key":"enabled","value":false,"network_transaction":{"version":1,"apk_sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","confirm_within_ms":60000}}}
```

规范化后的params包含现有默认`package:""`和`offset:0`，网络子合同参与原`request_digest`。窗口10000至120000毫秒；默认建议60000，必须显式传入。APK为原任务冻结的实际执行APK，不自行拿最新版本代替。服务器在新建任务时绑定当前设备凭据摘要，摘要不公开；新注册后的凭据不能继续旧事务。设备领取的`managed_task`增加网络任务专属`request_digest`；原`id/type/params/expires_at/idempotency_key/managed_exec_v1`保持。

## 独立确认

原任务claimed/running后由设备独立进程执行，不能排在普通任务忙槽之后。只对本地AWAITING_CONFIRM请求；不增加常态报告。

```json
{"device_id":"demo-device","token":"示例凭据","task_id":"network-demo","state":"running","action":"network-confirmation","network_confirmation":{"version":1,"request_digest":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb","task_id":"cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc","apk_sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","key":"wifi_enabled","before":true,"target":false,"boot_id":"00000000-0000-4000-8000-000000000001","started_elapsed":100000,"deadline_elapsed":160000,"window_ms":60000,"issued_elapsed":101000,"last_elapsed":100900,"nonce":"00000000-0000-4000-8000-000000000002"}}
```

内层task_id必须实际等于`SHA-256(UTF-8(device_id+":"+云端task_id))`，示例c重复摘要只是占位，不能直接用于验收。设备核对实际request_digest，不自行重算Web规范化规则。

服务器验证身份、原任务running、未停用/取消/过期、目标/APK/窗口/摘要及本地任务号。首次持久绑定`task_id/apk_sha256/key/before/target/boot_id/started_elapsed/deadline_elapsed/window_ms`；以后不允许变更。`last_elapsed`只是本次防倒退检查，不加入不可变绑定；`issued_elapsed`不得倒退。首次确认还保存服务器最晚发放时间，后续重试不可续期。

成功响应：

```json
{"ok":true,"device_id":"demo-device","task_id":"network-demo","request_digest":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb","network_confirmation":{"version":1,"decision":"allow","task_id":"cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc","apk_sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","key":"wifi_enabled","before":true,"target":false,"boot_id":"00000000-0000-4000-8000-000000000001","started_elapsed":100000,"deadline_elapsed":160000,"window_ms":60000,"issued_elapsed":101000,"nonce":"00000000-0000-4000-8000-000000000002"}}
```

成功只表示允许已持久发放，原任务仍running。响应不回传凭据。身份错误401；原号/绑定/状态错误409；原任务不存在404；无确认时绝不返回`decision:allow`。同nonce同请求幂等；同nonce换参数拒绝。新poll必须新nonce，已接受请求时间不得倒退。设备只接受本次在途nonce，回包后及提交锁内重验原boot/期限/目标，严格`now<deadline`。HTTP全链路预算不超过剩余窗口及3000毫秒，恢复守护独立运行。

## 进度与终态

普通claimed/running可以没有result；一旦携带网络结果，必须使用`result.network_transaction`结构，不用普通exit_code=0提前成功。结构例子如下，其中binding为上文九个固定字段，不包含nonce或issued_elapsed：

```json
{"device_id":"demo-device","token":"示例凭据","task_id":"network-demo","state":"success","result":{"network_transaction":{"version":1,"status":"CONFIRMED","binding":{"task_id":"cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc","apk_sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","key":"wifi_enabled","before":true,"target":false,"boot_id":"00000000-0000-4000-8000-000000000001","started_elapsed":100000,"deadline_elapsed":160000,"window_ms":60000},"observed_elapsed":102000,"current_enabled":false,"cleanup_complete":true,"restored":false,"confirmation_nonce":"00000000-0000-4000-8000-000000000002"}}}
```

- CONFIRMED：必须匹配已发放允许及其nonce，观察时间在允许请求时间至原deadline之前，当前开关为目标，cleanup_complete=true才外层success。清理未完成保持running，允许随后按原号补传完成。
- UNCHANGED：before等于target且current_enabled为原值，cleanup_complete=true可success，显示“原配置已符合，未修改”；不声称管理链路验证。
- ROLLED_BACK：current_enabled等于before且restored=true，清理完成后外层failed，显示“已恢复原配置”。
- ORIGINAL_OBSERVED：current_enabled等于before、restored=false；外层failed，显示“原配置未改变”，不声称执行过恢复。
- ABORTED：终止且清理完成后failed，不自动写成回滚成功。
- AWAITING_CONFIRM、NEEDS_ATTENTION、UNKNOWN和清理未完成：外层running，保持普通槽等待原号核查；current_enabled可为null，已知结果必须是布尔。
- result中版本、状态、binding、observed_elapsed非负整数、current_enabled布尔或null、cleanup_complete/restored布尔均必填；只有CONFIRMED要求confirmation_nonce。重复终态必须内容一致，不覆盖不同终态。

已领取网络任务到服务器期限后停止发放允许，但保留原参数和普通忙槽等待设备实际终态，不由服务器时间推断已回滚。尚未领取的pending可按原逻辑过期。允许已发放后取消返回`cancel_outcome:"confirmation_already_issued"`及原任务，不承诺撤销已在途回执；发放前取消设原cancel_requested，阻止允许，等待设备原号回执。晚到终态按原号及原绑定校验；未知/未决记录不能自动清理。明确终态历史沿现行30天规则，不冒充无限幂等。

网络目标本批不加入自动配置恢复队列，避免清数据或换APK后自动重放旧网络事务。浏览器仅原号查询，可显示公开`task.network`中的确认阶段与结构化结果；设备身份和秘密摘要不公开。

## 验证与交付界限

至少覆盖错身份/旧凭据、错绑定/nonce、同号不同参数、忙槽确认、请求丢失、取消竞态、截止相等、跨boot、恢复先完成、DO重建、终态ACK丢失和D22旧系统配置回归。没有设备新鲜能力报告、独立Source及守护真实验收时，不提前开放网络控件。只实施现有页面所需状态透传，不进行额外UI重设计或丢失模式开发。

## 第十二批实施补充：验收门、随机号及未开始拒绝

- 服务端私有配置 D31_NETWORK_ACCEPTANCE_JSON 可限定一条设备记录、一个候选APK完整摘要和不超过24小时的短期expires_at。仅匹配目标且已报告managed_network_confirmation_v1=true的D31可由管理员原task接口验收；network_write仍false、网页不开开关。默认未配置即不允许；配置不写进公开仓库。
- 原任务最多保存64个nonce及各自请求/允许回执。同nonce换参数即拒绝，包括先A后B再改写A；新poll不撤销先前已合法发放的允许。设备最终confirmation_nonce可匹配本原任务保存的任一允许，但必须在相应请求时间至原deadline之前真实完成提交。
- 开始前确知未进入网络begin且没有写入时，可上报state=rejected，result.network_transaction为：{"version":1,"status":"NOT_STARTED","binding":null,"mutation_started":false,"cleanup_complete":true,"restored":false,"current_enabled":null,"observed_elapsed":101000}。示例时间为合成值；客户端持久固定该结果。服务器仅在没有已有绑定、没有发放允许时接受；普通rejected/null不够。有执行意图而无法判断是否开始时必须继续原号核查，不能以NOT_STARTED掩盖未知状态。
- 已重新安装而归档成expired、仍没有设备实际完整终态的网络记录不按普通30天清除；不会把服务器到期或换凭据推断成已经回滚。

## 第十二批中间阶段兼容补充

D31实际持久日志在进程中断后可能停在PREPARED、APPLYING、ROLLING_BACK。Web接受这三项带完整原binding的结果，仅允许state=running且cleanup_complete=false，分别显示准备中、应用中、正在恢复原网络配置。不能直接转成success，不改变CONFIRMED和完整清理的成功条件，不混同UNKNOWN。新增本地测试覆盖三阶段通过、伪成功拒绝、伪清理完成拒绝及改绑拒绝。
