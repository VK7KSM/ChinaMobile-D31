### Android 6与链接安全审查

- 生产文件系统接口集中在`FileOperations.Access`。`Os.lstat/open/fstat/chown/chmod`及相关常量均为Android 6可用接口；没有在主类引入`java.nio.file`或依赖API 24才出现的比较器组合方法。
- 文件读取使用`O_NOFOLLOW`，并以描述符`fstat`核对普通文件；增加`O_NONBLOCK`，避免源文件被替换成管道时阻塞。临时文件使用`O_CREAT | O_EXCL | O_NOFOLLOW`创建，不能通过坏链接覆盖其指向路径。
- 递归访问前检查父目录是否改成链接，并在逐子项处理和删除之前检查对象身份。显式路径的初始父目录别名仍可解析，例如Android存储别名。
- 这些检查并非基于目录描述符的原子遍历。路径检查与`listFiles/delete/renameTo`之间仍存在并发改名窗口；不能声称已抵抗恶意进程在同一目录持续交换链接或挂载点。父任务应把稳定隔离目录的行为验收与对抗性并发保证分开，不将本实现写成完全无竞态文件系统事务。
- 跨存储移动仍按既有合同明确失败并尝试恢复旧目标，没有偷偷改成复制后删除。成功覆盖保留备份；不承诺复制源权限、所有者或目录时间等未约定的元数据。

### API 23内的可用方案及保证范围

1. 普通文件的同文件系统发布可用API 21已有的`Os.link(source, target)`原子创建目标目录项：目标在系统调用时已经存在就返回`EEXIST`，包括既有符号链接或坏链接，不会替换其内容。成功后再移除原暂存名称；移动也可采用先建硬链接再移除源名称。测试替身用真实宿主`Files.createLink`验证相同目的名称冲突语义。
2. 硬链接保证的是这一次目标名称创建不覆盖。源路径、父目录或挂载点被并发替换仍需另行约束；普通复制和快照优先使用受保护的同目录暂存原件。删除旧名称不是与建链接合一的原子事务，成功建链接后删除失败或进程退出可能留下两个名称；需要明确已提交状态、保留源/暂存和恢复判据，不能简单按“整体未完成”再覆盖目标恢复旧备份。
3. 旧目标备份、最终发布和恢复均需一致使用不覆盖原语并正确区分“尚未发布”和“已发布但旧名称未清理”。文件系统不支持硬链接、跨文件系统或权限拒绝时必须明确失败并保留相关原件，不能退回覆盖式`renameTo`声称仍具有相同保证。D31各存储挂载的支持情况尚未真机验证。
4. 目录不能采用硬链接。API 23公开的`android.system.Os`没有可直接用于本工程的`renameat2(RENAME_NOREPLACE)`接口；普通`rename`不能提供目录原子禁止覆盖。原子`mkdir`可占用不存在的目标名称后再逐项排他复制，但整个目录不是一次性发布，且不等于现有目录移动；其取消、可见中间态和恢复合同都需要另行实现。不能只先建立空目录占位后再覆盖式重命名，就声称阻止了不遵守锁的并发写者。
5. 当前目录移动或目录整体替换的可保证范围只能限定为父目录和涉及目录项不被外部同时修改，或所有写者确实遵守同一互斥协议。进程内锁、任务编号和检查重试无法约束其它进程。若以后引入原生无覆盖重命名能力，须验证实际内核、文件系统和错误语义，不能由Android版本推定支持。本轮不新增原生模块、不全局禁用功能、不修改Web。
